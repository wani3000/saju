- `npm test`: **41/41** 통과. 기존 30건에 OAuth 시도 소유권·만료·중복, 명시적 병합(결과/주문/공유/무료 이력), 생일 충돌·계정 전환, 삭제 후 복구 차단·늦은 worker, 비활성 비회원 정리, 결제 미확정 삭제 차단·대사, 삭제 후 늦은 환불, NICEPAY 위변조·다른 주문·반환 토큰·응답 유실 테스트를 추가했다.
- `npm run test:postgres`: 로컬 PostgreSQL 17 임시 클러스터, 독립 연결 풀 2개, 동시 무료 요청 12개 중 예약 1개, SKIP LOCKED 작업 획득 1개, 중복 승인 이용권 1개, 환불 후 늦은 worker 차단. 서버 role의 CREATE/DROP/migration ledger 변경 거절 확인. pg_dump custom → 새 DB pg_restore 후 결과 스냅샷 전체 일치. 테스트 클러스터는 종료·삭제했다.
- `npm run build`, `npm run db:check`, `npm run test:http` 통과. HTTP 여정에 미설정 OAuth 거절, 무효 병합 토큰, 개인정보 삭제·복구 코드 폐기를 추가했다.
- 브라우저: 합성 20명, 4명씩 5페이지, 마지막 17~20번 카드와 다음 비활성화, 20명 목록 확인. [390px 지도](qa/map-20-mobile.png): 문서 너비=viewport=390.
- 실제 Chrome 메뉴에 **확대/축소 200%** 표시를 확인했다. [지도](qa/map-200-percent.png)와 [보관함](qa/account-200-percent.png)의 문서 너비=viewport=855. 확인 후 배율100%와 임시 viewport를 복원했다. 전체 화면·텍스트 전용 확대·모든 보조기기 준수 판정은 아니다.
- React 검수: 결제사 SDK는 결제 시작 때 로드하고 비밀키는 서버 모듈에만 둔다. 로그인/병합/삭제 요청은 세션·Origin 검사를 통과해야 한다. 보관함 전환 시 기존 자동 저장 큐를 마친 뒤 계정을 바꾸고 이후 대기 저장을 차단한다. 삭제 버튼은 확인 체크 전 비활성화한다.

NICEPAY 테스트는 실제 네트워크 결제가 아니라 서명된 API 응답 fixture를 주입한 검증이다. 실제 `ready` 거래 조회·승인·취소·웹훅, Supabase 카카오 로그인 왕복, 실제 사용자 관찰, 운영 정책과 궁합 규칙 감수는 미완료다. 전자책 프로젝트의 비밀키·운영 거래를 사용하지 않았다.

추가 DB 경계 검증: 호스팅 기본 권한을 모사해 별도 익명 role에 모든 테이블 DML 권한을 부여해도 RLS가 계정·결과 조회를 0행으로 제한하고 INSERT를 거절하며 UPDATE도 0행임을 확인했다. migration owner와 runtime role은 기존 여정을 계속 통과한다.
