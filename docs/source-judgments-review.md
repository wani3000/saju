# 통근 등급·합 방해 사례 후속 감수 · 2026-10-19

## 반영 범위

[앞선 조건 관찰](month-combination-review.md)에서 남긴 통근 등급과 합 방해 조건 중, 『子平真詮』 1926년 판본에 **직접 적힌 사례**를 별도 연구 해석으로 구현했다. `ziping-explicit-judgments-research-v1`은 단순히 같은 오행을 찾는 기능을 넘어 해당 판본의 분류를 반환한다. 다만 사례집에 없는 조합까지 확대하는 완성된 통근표나 강약·합화 종합 엔진은 아니다.

[원본 PDF](../research/validation/fixtures/reading-sources/ziping-1926-vol2.pdf)의 PDF 20~22쪽(인쇄 七~九)을 다시 육안 대조했다. [새 전사](../research/validation/fixtures/reading-sources/judgment-transcription.json)와 [무결성 정보](../research/validation/fixtures/reading-sources/judgment-source.json)를 별도로 고정했다. 기존 전사·연구 버전·감수 보고서는 수정하지 않았다. 현대 해설이나 모델의 기억으로 누락된 표를 채우지 않는다.

## 뿌리 분류

| 일간·지지 | 이 판본의 명시적 분류 | 적용 |
|---|---|---|
| 갑·미, 병·술 | 묘고, 가벼운 뿌리 | `tomb`, `light` |
| 을·술, 정·축 | 지지 안에 해당 목·화가 없어 앞의 묘고 설명에서 제외 | `excluded-as-tomb`; 전체 사주 무근 판정은 아님 |
| 을·진, 정·미 | 여기, 가벼운 뿌리 | `residual`, `light` |
| 갑·해, 갑·인, 갑·묘 | 장생·록·인, 무거운 뿌리 | 각각 `birth`, `salary`, `blade`; `heavy` |
| 을·오, 정·유 | 음간 장생은 앞의 무거운 뿌리 설명과 구분하지만 뿌리가 있다고 함 | `yin-birth-root`; 등급은 null |

원문은 비견 하나·둘·셋보다 묘고·여기·장생록인의 뿌리를 중시하는 설명을 한다. 이를 1:1, 2:1, 3:1 수치로 변환하지 않는다. `light`와 `heavy`는 이 저자의 정성적 분류이며 측정된 예측력·점수가 아니다. 양·음간 전부의 장생표, 토의 별도 취급이나 다른 판본까지 외삽하지 않는다.

**을·오와 정·유는 중요한 정의 차이**다. 기존 지장간 목록에는 각각 같은 목·화가 없지만, 이 원문은 해당 음간 장생의 뿌리를 인정한다. 따라서 기존 `rootObservations`를 덮어쓰지 않고 새 `rootAssessments`에 출처별 판단을 남긴다. ‘지장간에 같은 오행 없음’과 ‘어떤 통근 학설에서도 뿌리 없음’을 같은 의미로 사용하지 않는다.

10천간×12지지 120조합 중 이번 사례집에 명시적으로 반영한 것은 11조합이다. 나머지 109조합은 `not-covered-by-selected-examples`다. 이는 잘못된 입력·뿌리 없음·신약을 의미하지 않는다. 각 위치에 후보별 분류와 사례집의 적용 범위를 함께 출력한다.

## 합 방해 판단

PDF 20쪽의 갑·기 사이 경, 갑·기 사이 을이라는 두 사례를 적용했다. 기존 분석기에서 **갑기 합 짝의 실제 두 위치 사이**에 있는 경/을을 확인하고, 해당 판본의 방해 예에 부합하면 `source-obstruction-present`로 기록한다. 원문이 다루는 ‘사이에 있다’는 관계로 해석하므로 두 끝의 연·월·일·시 방향을 뒤집어도 같은 조건이다. 이 방향 정규화는 구현 정책이다.

다른 천간 합, 두 끝 바깥의 극, 멀리 떨어졌다는 사실만으로는 이 판정을 내리지 않는다. 사례가 없으면 미판정으로 남기고, 이를 ‘방해 없음’이나 ‘합화 성립’으로 바꾸지 않는다. 갑기라는 기호 관계 자체도 삭제하지 않는다. 원문의 `合而不敢合`에 해당하는 부분 판단과, 오행이 실제로 바뀌는 합화의 종합 판단은 구분하며 `transformation.element`는 null이다.

후보마다 경 또는 을로 방해하는 경우에는 ‘원문 방해 사례 중 하나가 모든 후보에서 나타남’을 기록할 수 있다. 그러나 경/병 후보처럼 일부에만 방해가 있거나 갑기 짝 자체가 일부에만 있으면 `candidate-dependent-obstruction`으로 남기고 확정 문장에서는 제외한다. 알려지지 않은 시주의 관찰 부재를 전체 차트의 부재로 읽지 않는다.

## 풀이·검증

[감수 문장 16사례](../research/validation/reports/source-judgment-drafts.md)와 [기계 판정](../research/validation/reports/source-judgment-audit.json)을 생성했다. 문장에는 『子平真詮』에 따른 해석임을 표시하고, 묘고 제외를 전체 무근으로 확대하지 않는다. 신강·신약, 용신, 궁합 점수는 산출하지 않는다. 기존 앱의 예시 풀이·구매 스냅샷·지도·공유는 변경하지 않았다.

신규 12개 검사는 다음을 확인한다.

- 원본 스캔·쪽 이미지·새 전사 해시, 카탈로그와 반환값의 변경 격리.
- 120조합의 11개 사례 및 미수록 상태, 음간 장생과 기존 지장간 관찰의 차이.
- 같은 일주 후보 안의 일간·지지 결합, 일부 월주 후보의 판단 제외.
- 원문 두 방해 사례, 끝의 방향 교환, 범위 밖의 극, 다른 합, 합 짝 자체의 불확실성.
- 16개 주변 조합을 고정 차트로 전개한 결과와 불확실성 처리의 일치.
- 시간 모름·역사 시계·절기 검토·음양력 대응·비공개 필드 제외, 기존 보고서 재현.

전체 연구 테스트 104개, 엔진 빌드, 문서 연결 및 보고서 재현 검사를 통과했다. `--release-check`는 계속 미승인 종료 코드 2다. 이 검사는 구현의 일관성과 원문 추적성을 확인하며 전통 풀이의 예측 타당성을 증명하지 않는다.

```sh
node research/validation/audit-source-judgments.mjs --check
pnpm --dir research/validation test
# 운영 미승인: 종료 코드 2
node research/validation/audit-source-judgments.mjs --release-check
```

## 남은 순서

사령의 절기 내 일수 정책과 나머지 통근 사례를 비교해 종합 강약 기준을 정하고, 합화 성립의 충분조건과 상충 규칙을 추가 감수해야 한다. 이번 부분 분류로 강약 감수가 모두 끝났다고 처리하지 않는다. 그 뒤 관계별 해석, 점수·지도 척도, 승인된 결과의 웹 연결을 진행한다. 실제 사용자 관찰과 역사 시각·독립 음양력 검증 확대는 기존 남은 항목이며 외부 연동은 준비 후 진행한다.
