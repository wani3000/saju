# 순차 개발 실행 계획

기간을 먼저 약속하기보다 검증 결과로 다음 단계 진입을 결정한다. 아래는 한 개발 흐름을 순차 진행하는 계획이며 병렬 에이전트 실행을 전제로 하지 않는다.

## P00 문서와 위치 준비

산출물: 현재 README·AGENTS·TASKS·설계 문서·참고 화면·문서 검사 도구. 2026-10-09 권한 변경 후 Documents/github/saju-relationship에 배치했다. 기존 폴더가 없음을 확인하고 복사했다.

완료 조건: 문서 연결 검사 통과, 실제 위치 확인. 현재 문서 준비와 요청 위치 배치를 완료했다.

## P01 사주 계산 검증

작업: 후보 라이선스/코드 확인, 버전 고정, 정규 입력/출력 어댑터 실험, 독립 대조 사례, 미상 시간, 과거 시간 정책, 궁합 규칙 감수 계획.

산출물: engine-validation.md, 출처 있는 fixtures, 테스트 로그, 채택/불채택 결정 기록. 실제 운영 API 계약은 필요 없다.

완료 조건: 지원 범위와 정책 확정, 치명 불일치 해결. 해결되지 않으면 범위 축소 또는 대안 선택. 감수되지 않은 점수로 출시하지 않는다.

## P02 큰 글씨 사용자 경험

작업: 첫 무료 흐름과 두 번째 유료 흐름의 화면안, 입력·로딩·실패·빈 지도·목록·공유 미리보기. 적용 스킬의 시각안 선택 절차를 따르고 사용자에게 구체적 화면을 보여준다.

산출물: 선택된 디자인, 디자인 토큰, 핵심 컴포넌트 명세, 화면별 문구. 원 사이트 자산은 사용하지 않는다.

완료 조건: 글씨와 버튼 기준 충족, 전체 클릭 흐름 설명 가능. 새로운 디자인이 선택되기 전에 임의로 완성 UI를 고정하지 않는다.

## P03 앱 골격

작업: 적절한 런타임/패키지 버전을 고정하고 앱·서버·테스트 골격 생성. 합성 결과로 화면과 이동 구현. lint/typecheck/build·핵심 단위 테스트 실행.

산출물: 로컬 실행 가능한 앱, 실행 README, 환경 변수 이름만 담은 예제, CI 설정. 외부 secrets 없이 mock 모드 실행 가능.

완료 조건: 내 입력 → 상대 입력 → 가상 결과 → 가상 지도까지 오류 없이 동작, 모의 데이터임이 분명함.

## P04 DB와 계정

작업: migration, RLS/grants, 계정·person·birth version, 익명 세션, 영구 계정 연결, 입력 복원, 충돌 처리. 필요한 시점에만 Supabase/인증 공급자 준비물을 연결한다.

산출물: 새 DB와 기존 DB 모두에 적용 가능한 migration, 합성 seed, 교차 소유권·계정 연결 테스트.

완료 조건: 새로고침 후 초안 복원, 다른 사용자 정보 접근 차단, 무료 이력 이관 검증.

## P05 첫 무료 결과

작업: 검증 엔진과 승인된 rule/template release 연결. 개인 계산 캐시, comparison, 무료 예약, job lease/fencing, 결과 저장과 entitlement 구현.

산출물: 실제 계산으로 첫 무료 결과. 실패/재시도 화면과 지원 가능한 입력 범위 안내.

완료 조건: 동시 무료 요청에서 한 건, 미상 시간 오염 없음, worker 중단/재시도 복구, 동일 입력 결정성. 감수 미완료 상태에서는 내부 테스트만 가능.

## P06 지도와 공유

작업: q→반경 매핑, 각도 보존, 사람 선택, 목록 대체, 공개 스냅샷, 링크 발급·철회·만료, 공유 미리보기.

완료 조건: 1/2/8/20명에서 읽고 선택 가능, 다른 사람 추가로 기존 점수 변화 없음, 생일/다른 지도 누출 없음.

## P07 두 번째 상대 결제

작업: PG 테스트 환경, 서버 가격, 주문/승인/이용권, 웹훅 중복 처리, 정기 대사 로직, 결제 후 생성 실패·환불 복구.

완료 조건: 테스트 2,900원 주문 → 결과 → 지도 → 재열람 성공, 승인 응답 유실과 중복 이벤트 테스트 통과. 실결제는 PG 계약 및 별도 실행 범위 확인 후 진행.

## P08 전체 검증

작업: docs/09의 인수 사례, 실제 모바일 브라우저와 큰 글씨·확대·보조기기 검증, 소규모 성인/고령 사용자 관찰, 성능 측정, 개인정보 응답 점검.

산출물: QA 보고서와 수정 내역. 완료 조건: 출시 차단 결함 0, 주요 사용자 과제의 막힘 해소.

## P09 운영 준비와 출시

작업: 서비스 이름/운영주체/고객지원/약관·개인정보·환불 고지 확정, 도메인·호스팅·운영 DB·PG 계약 준비, 백업 복원과 정합성 복구 리허설, 운영 로그·알림 점검.

산출물: launch-checklist.md, 운영 runbook, 비용표, 실제 배포 요청에 대한 구체적 변경 목록.

완료 조건: 사용자 요청 범위에 맞춘 실제 배포 후 URL에서 전체 핵심 흐름 확인. 문서 작성이나 staging 성공을 운영 출시로 표시하지 않는다.

## 단계 종료 기록

TASKS.md에 완료 근거 파일, 실행한 명령/테스트, 실패와 해결, 남은 선택, 다음 단계를 기록한다. 예상과 실제 범위가 바뀌면 관련 설계와 가격·데이터 정책을 함께 갱신한다.
