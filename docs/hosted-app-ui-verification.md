# 실제 카카오 로그인 앱의 사주·결제·프로필 검증

2026-10-23. 대상은 전용 연구용 서버 `https://chunbae-staging.vercel.app/`다. 별도 루프백 검증 도구를 사용하지 않고 Chrome의 실제 앱 화면에서 진행한다. 생일/이름은 검증용 가상 정보이며 실제 카카오 identity·프로필·원래 무료권 정책을 사용한다. 사용자 생일이나 인증·주문 식별자는 문서/로그/Git에 남기지 않는다.

## 확인한 경계

- 기존 앱 세션 로그아웃 → 카카오 로그인 버튼 → 공급자 왕복 → 로그인 성공 안내와 내 생일 입력 복귀.
- 가상 정보 입력 → 첫 무료 결과 생성 → 여덟 글자·개인 장단점·친구별 설명 표시. 서버에 결과1개와 소비된 무료권, 카카오 프로필 저장을 읽기 전용으로 대조했다.
- 프로필 조회 내역에서 무료 결과 재열람, 새로고침 뒤 로그인/조회 내역 유지. 무료 이야기는 결제 내역에 나타나지 않았다.
- 다른 가상 상대/연인 관계 추가 → NICEPAY sandbox 2,900원 created 주문과 awaiting_payment 비교 생성. 키나 금액을 클라이언트에서 조작하지 않았다.
- 실제 앱 테스트 결제창·인증 뒤 결과와 프로필 결제/조회 내역은 아래 후속 검증을 기다린다. 이 단계까지 완료로 표시하지 않는다.

## 발견한 문제와 수정

프로필은 결제 대기 상태를 `awaiting-payment`로만 비교했지만 서버는 `awaiting_payment`를 반환했다. 실제 앱의 결제 전 이야기가 ‘준비 중’으로 보이는 것을 재현했다. 서버 이름과 보존된 정적 체험판의 이름을 모두 인식하도록 수정했다. 로컬 모바일 회귀는 무료 내역/결제 내역 분리 → 결제 대기 안내 → 주문 이어가기 → 모의 승인/조회 → 모의 취소/열람 회수 → 원래 무료 결과 재열람을 확인한다. 로컬 보관 회원은 복구 방식이며 실제 카카오 인증 증거로 대체하지 않는다.

빌드 중 Next.js16.4.0의 보안 권고와 npm 감사 critical1건을 확인했다. [공식 보안 안내](https://nextjs.org/blog/nextjs-security-update-october-14-2026)를 대조하고 같은16.4 계열16.4.2로 고정 업데이트했다. npm 감사 결과0건이다. 실제 공격이나 정보 유출을 확인했다는 뜻은 아니다. 엔진·규칙·기존 결과·연구 모드·실청구 차단은 유지한다.

## 검증 진행 상태

단위/서비스165개, Next16.4.2 빌드·타입, 일반 HTTP/모바일28개 통과. 카카오 필수 HTTP/모바일2개·별도 NICEPAY HTTP·Vercel prebuilt 빌드도 통과했다. 스테이징 재배포와 실제 앱 결제 왕복은 이어서 진행한다. 무료권을 DB에서 되돌리거나 실제 카카오 계정을 가상 계정으로 바꾸지 않았다. 검증용 기록은 실제 앱 프로필에서 구분해 볼 수 있도록 별명을 사용한다.
