# 실제 카카오 로그인 앱의 사주·결제·프로필 검증

2026-10-23. 대상은 전용 연구용 서버 `https://chunbae-staging.vercel.app/`다. 별도 루프백 검증 도구를 사용하지 않고 Chrome의 실제 앱 화면에서 진행한다. 생일/이름은 검증용 가상 정보이며 실제 카카오 identity·프로필·원래 무료권 정책을 사용한다. 사용자 생일이나 인증·주문 식별자는 문서/로그/Git에 남기지 않는다.

## 확인한 경계

- 기존 앱 세션 로그아웃 → 카카오 로그인 버튼 → 공급자 왕복 → 로그인 성공 안내와 내 생일 입력 복귀.
- 가상 정보 입력 → 첫 무료 결과 생성 → 여덟 글자·개인 장단점·친구별 설명 표시. 서버에 결과1개와 소비된 무료권, 카카오 프로필 저장을 읽기 전용으로 대조했다.
- 프로필 조회 내역에서 무료 결과 재열람, 새로고침 뒤 로그인/조회 내역 유지. 무료 이야기는 결제 내역에 나타나지 않았다.
- 다른 가상 상대/연인 관계 추가 → NICEPAY sandbox 2,900원 created 주문과 awaiting_payment 비교 생성. 키나 금액을 클라이언트에서 조작하지 않았다.
- 실제 앱 테스트 결제창·현대 앱 인증·직접 hosted return 뒤 유료 결과와 프로필 결제/조회 내역까지 확인했다. 아래 최종 왕복 기록을 따른다.

## 발견한 문제와 수정

프로필은 결제 대기 상태를 `awaiting-payment`로만 비교했지만 서버는 `awaiting_payment`를 반환했다. 실제 앱의 결제 전 이야기가 ‘준비 중’으로 보이는 것을 재현했다. 서버 이름과 보존된 정적 체험판의 이름을 모두 인식하도록 수정했다. 로컬 모바일 회귀는 무료 내역/결제 내역 분리 → 결제 대기 안내 → 주문 이어가기 → 모의 승인/조회 → 모의 취소/열람 회수 → 원래 무료 결과 재열람을 확인한다. 로컬 보관 회원은 복구 방식이며 실제 카카오 인증 증거로 대체하지 않는다.

빌드 중 Next.js16.4.0의 보안 권고와 npm 감사 critical1건을 확인했다. [공식 보안 안내](https://nextjs.org/blog/nextjs-security-update-october-14-2026)를 대조하고 같은16.4 계열16.4.2로 고정 업데이트했다. npm 감사 결과0건이다. 실제 공격이나 정보 유출을 확인했다는 뜻은 아니다. 엔진·규칙·기존 결과·연구 모드·실청구 차단은 유지한다.

## 검증 진행 상태

단위/서비스165개, Next16.4.2 빌드·타입, 일반 HTTP/모바일28개 통과. 카카오 필수 HTTP/모바일2개·별도 NICEPAY HTTP·Vercel prebuilt 빌드도 통과했다. 스테이징 재배포와 실제 앱 결제 왕복도 아래 최종 기록대로 확인했다. 무료권을 DB에서 되돌리거나 실제 카카오 계정을 가상 계정으로 바꾸지 않았다. 검증용 기록은 실제 앱 프로필에서 구분해 볼 수 있도록 별명을 사용한다.


## 결제창 지연 호출 문제

소스0e315e5 배포에서 프로필의 결제 대기 안내는 정상으로 바뀌었고, 기존 세션/무료 결과도 보존됐다. 그러나 실제 앱의 결제 버튼은 SDK의 빈 iframe을 만든 뒤 busy 상태로 남았다. 주문은 created였고 아직 카드 인증/승인이 시작되지 않았다.

공식 SDK를 그대로 사용하는 별도 루프백 표시 진단에서 즉시 호출은 정상이고, 동일 호출을 클릭 뒤6초 지연하면 같은 빈 프레임을 재현했다. no-referrer 및 앱과 같은 X-Frame-Options/Permissions-Policy 조건의 즉시 호출은 정상이라 보호 헤더는 변경하지 않았다. 표시 진단은 카드 인증·승인 없이 종료했다.

결제 정보 요청과 공식 SDK 로딩을 전용 버튼 컴포넌트에서 미리 병렬 준비한다. 버튼 클릭 때는 네트워크 대기나 동적 import 없이 즉시 SDK를 호출하고, 브라우저의 활성 클릭 상태가 없으면 창을 만들지 않고 다시 누르도록 안내한다. 로딩 실패/창 닫기는 같은 주문에서 다시 준비할 수 있으며,5분 넘게 묵은 준비 정보는 새로 준비한다. 카드 인증 도중 nonce를 재발급하는 주기 타이머는 두지 않았다.

별도 NICEPAY 로컬 검사는 HTTP 외에 합성 SDK 모바일4개를 추가했다.6초 늦은 준비 뒤 새 클릭의 활성 상태, 닫기 후 재시도, SDK 로딩 실패 후 재시도와 미승인 주문1개 유지를 확인했다. 실제 NICEPAY 왕복 증거로 간주하지 않는다. React 점검: SDK는 필요할 때만 로드, 주문/요청 함수/재시도만 effect 의존성, unmount 뒤 상태 갱신 방지, SDK 중복 로드 방지, 실제 호출은 이벤트 핸들러, 버튼 disabled/오류 재시도 제공. 수정 후 실제 앱의 창 표시와 인증 왕복은 아래 배포 확인 기록을 따른다.

## 사전 준비 수정본의 실제 앱 확인

소스2840afb를 GitHub main에 올리고 Vercel에 배포했다. 배포dpl_5JpS16nYQVwykXx1neKULZyYHzay가 READY/서울이며 canonical alias도 같은 배포다. 실제 앱을 새로고침해 기존 주문을 복원한 뒤, 준비된 버튼을 누르자 공식 NICEPAY 카드 선택 화면이 정상적으로 나타났다. ‘테스트결제(실결제불가)’, 2,900원, 현대/일시불을 확인하고 현대카드 앱 인증 QR 단계까지 실제 앱에서 이동했다. 빈 프레임에 머무르던 현상은 이 경로에서 해소됐다.

이 중간 기록 시점에는 사용자 앱 인증을 기다렸다. 읽기 전용 대조에서 해당 주문은 created/awaiting_payment, 유효기간 내이며 결과0개·거래 이벤트0개다. 카드 인증 완료·자동 return·유료 결과/프로필 저장·테스트 취소는 아직 완료로 표시하지 않는다. 실제 계정 식별자와 QR/카드 세션 값은 Git에 저장하지 않는다.

## 실제 앱 최종 왕복 결과

사용자가 마지막 현대카드 앱 인증을 마친 뒤 에이전트가 ‘결제 완료’를 눌렀다. NICEPAY에서 canonical 앱의 return으로 직접 복귀했고, 실제 카카오 계정의 프로필에 유료/무료 조회 기록2개가 표시됐다. 결제 내역은 ‘테스트 승인 완료 · 실제 청구 없음’ 2,900원이었다. 별도 루프백 전달·수동 승인·가짜 공급자/로그인은 사용하지 않았다.

조회 내역의 유료 결과를 열어 해·달·날·시간4기둥, 두 개인의 장단점, 연인용 총평·양방향 도움·서운할 때 대화·사랑의 습관·마무리를 확인했다. 결과 새로고침과 실제 앱 로그아웃→카카오 공급자 재로그인 뒤에도 두 조회 기록과 승인 내역이 유지됐다. 이는 렌더링/저장/관계별 본문 검증이며 명리 해석 운영 승인으로 확대하지 않는다.

승인받은 테스트 전액 취소를 프로필 버튼으로 실행했다. 결제 내역은 ‘테스트 취소 완료’, 해당 조회는 ‘이용이 취소된 이야기’로 바뀌며 다시 보기 버튼이 사라졌다. 기존 무료 친구 결과는 여전히 열렸고 새로고침 뒤에도 취소 상태가 유지됐다. 실제 청구는 없었고 실제 계정·무료권을 삭제/초기화하지 않았다.

제한 DB 역할의 읽기 전용 대조: 승인 시 paid/ready/active, 유료 결과1개·무료 결과1개. 최종 refunded/revoked, 서명·주문/금액을 검증하는 NICEPAY 조회 CANCELED, 서버 유료 결과 조회 NOT_FOUND·무료 결과 접근 성공, 승인 기록1건. [비식별 최종 보고서](audits/hosted-app-ui-roundtrip.json)에 범위를 고정한다.

실제 거래 웹훅 저장 이벤트는0개라 독립 통보 전달 성공은 확인하지 못했다. 이번 상태 갱신은 서명된 return과 직접 조회/취소로 확인했다. 관리자 등록 TEST/합성 HTTP 검증을 실제 거래 통보 증거로 대체하지 않는다. 운영 상점·실청구·다른 기기/카카오 인앱·프로필 미동의 실계정·외부 unlink/탈퇴·장기 운영/전문 감수·정식 출시 승인은 별도다.
