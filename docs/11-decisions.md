# 결정 사항과 준비물

## 사용자 의도로 확정된 제품 방향

- 어른들도 볼 수 있는 큰 글씨와 단순한 UX.
- 나와 상대의 생년월일 → 결과 → 공유 → 가까운 사람 지도.
- 한 명 추가를 반복할 수 있고 잘 맞을수록 지도에서 가까움.
- 첫 한 명 무료, 이후 유료 2,900원. 현재 계획은 상대 한 명당 과금.
- 프로젝트 계획과 실제 작업 순서를 로컬 폴더에 정리.

## 외부 준비물

- Supabase를 채택할 경우 dev/staging/prod 프로젝트, URL, 공개키, 서버 전용 키 및 DB 접속 경로.
- 간편 로그인 공급자 앱 등록, redirect URL, 비밀키. 첫 제안은 카카오를 검토하되 연동 가능 여부를 확인한다.
- NICEPAY 테스트 상점 설정, 운영 계약과 키, 사업자·정산 정보, 웹훅 주소. Toss는 이전 테스트 호환용.
- 운영 도메인과 DNS 권한, 배포 대상, 백업/모니터링 예산.
- 콘텐츠 감수와 운영 문의 담당자, 서비스 정책.

키는 비밀 저장소와 로컬 비추적 환경 파일로만 전달·보관한다. 문서에는 변수 이름과 용도만 기록한다. 지금은 어떤 키도 요구하거나 저장하지 않았다.

## 남은 위험과 대응

- 사주 엔진 정확도: 독립 경계 사례로 검증하고 통과 범위만 공개.
- 궁합 점수의 해석성: 고정 규칙과 감수, 실제 친밀도와 구분.
- 익명 무료 반복: 계정·세션 단위 제한, 과도한 식별 수집보다 비용/남용 관측.
- 결제/결과 불일치: 영속 job, 멱등 처리, 공급자 대사.
- 개인정보와 공유: 최소 수집, 원본과 공개 스냅샷 분리, 철회와 삭제.
- 큰 인원 지도: 축소 대신 목록/페이지로 접근성 유지.

## 2026-10-14 사용자 지정 결제사·운영 후속

전자책 플랫폼(다니엘의 노트)에서 사용한 NICEPAY를 사주 서비스의 우선 PG로 선택한다. 기존 Toss 테스트 어댑터는 호환용으로 유지한다. 전자책 상점의 운영 인증값·거래 DB는 재사용하지 않는다. NICEPAY 테스트 상점 `S2_`·sandbox만 허용한다.

정식 로그인 연결 코드는 Supabase PKCE·카카오로 준비한다. 현재 세션과 일회성 시작 시도를 확인하고 Supabase getUser() 결과만 신뢰한다. 기존 계정이 있으면 합치기/전환을 명시적으로 선택하며, 생일 충돌이나 진행 중 결제/job이 있으면 병합을 거절한다. 운영 계정 생성·배포와는 별개다.

삭제·보존 개발 정책: 직접 삭제는 개인 입력/결과/공유를 제거하고 최소 거래·동의·무료 이력/삭제 로그인 식별자를 남긴다. 만료 정리는 30일 이상 비활성·비회원·주문 없는 계정만 처리한다. 로그인 갱신·입력 저장과 동일한 계정 잠금에서 조건을 재검사한다. 보존 기간/근거는 출시 전 별도 감수가 필요하다.

## 2026-10-17 작업 복구 상한

자동 작업은 3회까지만 실행하며 worker 프로세스 중단도 소모한 시도로 취급한다. 3회 만료 시 무료 예약을 반환하고 유료 권한은 보존한다. 수동 재시도는 기존 비교 ID를 사용한다. 계정 삭제·환불·병합과 작업 획득의 잠금 순서를 계정→job으로 맞춘다. 수신 본문은 16KiB·10초 제한을 공통으로 적용하고 과대 요청 전체를 메모리에 받은 뒤 검사하지 않는다.
