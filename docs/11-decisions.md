## 2026-10-14 사용자 지정 결제사·운영 후속

삭제·보존 개발 정책: 직접 삭제는 개인 입력/결과/공유를 제거하고 최소 거래·동의·무료 이력/삭제 로그인 식별자를 남긴다. 만료 정리는 30일 이상 비활성·비회원·주문 없는 계정만 처리한다. 로그인 갱신·입력 저장과 동일한 계정 잠금에서 조건을 재검사한다. 보존 기간/근거는 출시 전 별도 감수가 필요하다.

## 2026-10-17 작업 복구 상한

자동 작업은 3회까지만 실행하며 worker 프로세스 중단도 소모한 시도로 취급한다. 3회 만료 시 무료 예약을 반환하고 유료 권한은 보존한다. 수동 재시도는 기존 비교 ID를 사용한다. 계정 삭제·환불·병합과 작업 획득의 잠금 순서를 계정→job으로 맞춘다. 수신 본문은 16KiB·10초 제한을 공통으로 적용하고 과대 요청 전체를 메모리에 받은 뒤 검사하지 않는다.

운영 점검은 실패 작업·만료 lease·미확정 결제의 존재를 조치 필요로 판정한다. 임의의 지연 SLA를 운영 기준으로 확정하지 않는다. 점검 정상은 DB 내 해당 이상이 없다는 의미이며 외부 로그인/PG 검증·콘텐츠 승인·출시 허가를 뜻하지 않는다. 상태 집계만 CLI로 출력하고 실제 알림 발송이나 예약 실행은 만들지 않는다.

『三命通會』 선호 시주 뒤의 기피를 월 문맥·일시 위치에 한정해 관찰한다. 무계의 일지 조건을 누락하지 않으며 선호/기피 공존·시간 미상·후보 상관관계를 보존한다. `除月/余月` 등 온라인 전사 차이는 원본 자동 교정이나 충분조건 판정에 쓰지 않는다. `若犯戊己`의 미확정 범위를 모든 천간으로 확대하지 않는다.

오행 구비와 중화는 구분하며 원문 극단 20사례 중 8개가 해당 지름길의 반례다. 개인 명조의 기피나 강약을 두 사람의 관계 효과·가중치로 전용하지 않는다. 새 연구 판단은 null 상태의 최종 결론을 유지하며 기존 앱·구매 결과와 이전 보고서는 변경하지 않는다.

## 2026-10-20 왕기·구응과 합화 전후 판단 대상

[化象 원문 4사례](rescue-wangqi-review.md)는 해당 판본의 정확한 기둥 일치에만 귀속한다. 추가 갑을의 제어와 진화 판어, 辰 없는 진화 사례를 보편 왕기 알고리즘으로 확대하지 않는다. 이미 진화한 뒤의 예외로 진화 전제를 스스로 증명하지 않으며, 화신의 부족/유여를 원일간 강약으로 옮기지 않는다. 기존 출처별 부정 조건과 새 원문 판어는 병기한다.

『子平真詮』의 격국 구응은 실제 격국·손상·힘·배치가 미확정인 관찰 모델이다. 정적 월지 후보가 격국을 확정하지 않고 지장간 인성을 투출 인성으로 보충하지 않는다. 인성의 유익/방해가 문맥별로 다른 근거를 개인 간 가감점으로 전용하지 않는다. 합성 상대 가중치의 순위 역전은 민감도 진단이며 추천 산식이나 관계 관측값이 아니다. 운영 승인·기존 앱 결과는 유지한다.

## 2026-10-20 직접 가능한 출시 준비 일괄 수행

사용자가 개발자가 할 수 있는 작업을 순서대로 모두 진행하도록 요청했다. [계산 정책 권장안](calculation-policy-candidate.md)은 현재 v5의 관습과 보호를 안내·테스트로 고정하며 최종 운영 승인을 주장하지 않는다. 신규 안내는 현재 입력 화면에만 적용하고 저장된 계산/풀이 스냅샷을 변경하지 않는다. 과거 시계 중복·소실과 환산 범위 오류를 서로 다른 사유로 안내한다.

입력 초안이 결과 확인 동의 이전부터 자동 저장되는 실제 동작을 입력칸 앞에 명시했다. 운영 동의·제3자 입력·보존 기간은 [운영 초안](launch-operations-runbook.md)에서 별도 확정 항목으로 남긴다. 안내 문구 추가로 법적/운영 승인이 완료됐다고 보지 않는다.

[감수 실행 묶음](launch-review-kit.md)은 17문구·22원문 명조·4합화 사례·3구응 구조의 빈 46항목과 실제 사용자 세션 양식을 제공한다. 자동 생성은 근거 해시·버전·8개 조건·담당 역할을 재현하고, 참가자 수/전문가 승인/범위가 바뀌면 먼저 근거 조정을 요구한다. 참가자 0명·전문가 서명 없음·실결제 차단을 유지한다. 실제 기록은 공개 Git에 저장하지 않는다.

운영 점검은 queued 작업이 붙은 비교의 최초 생성 후 300초 이상을 `DELAYED_QUEUE`로 알린다. 재시도 후 경과 시간은 순수 큐 체류 시간이 아니며 300초는 운영 SLO가 아니다. 정상 큐·만료 lease·실패·미확정 결제와 구분한다. 이 보완에는 스키마 변경·운영 배포·알림 등록·외부 키 조회가 없다.

## 2026-10-20 조선 남자 할아버지 방향

사용자가 흑백 실내 장면과 여성 노인 캐릭터 서비스 캡처를 참고로 조선 콘셉트·남자 할아버지를 요청했다. 최신 방향은 [조선 시안](../design/characters/joseon/README.md)으로 변경한다. 실제 생성 이미지가 표시된 순서대로 1·2·3이며 세부 선택은 대기다. 원본 참고를 생성 호출에 첨부하고 가상의 남성 얼굴과 별도 화면을 만들었다. ‘사주 할아버지’는 가칭이다.

이번 작업은 독립 시안 3개와 제작 기록이며 앱 적용/디자인 선택 완료가 아니다. 현재 호랑이 구현·자산·구매/공유 스냅샷은 보존한다. 참고 서비스의 캐릭터채팅 기능은 채택하지 않고 기존 두 사람 생일 입력·기호 설명 흐름을 유지한다. 선택한 안의 실제 적용 뒤 별도 시각·접근성·기능 회귀 검증을 수행한다.

## 2026-10-20 시선·실제 앱 참고 후속

사용자는 카메라를 보지 않는 조선 노인을 옛 미국 선교사의 기록 사진 같은 느낌으로 요청했고, 예시 앱을 실제로 확인해 디자인 분위기를 반영하도록 추가 지시했다. [공개 화면 확인](guija-design-reference-review.md)은 공식 앱 미리보기 5장과 실제 웹 소개→안내→입력을 구분해 기록했다. 설치 앱 내부 대화·기억·결제는 실행하지 않았다.

책을 내려다보는 가상 남성 장면 1개와 [새 UI 3안](../design/characters/joseon/documentary-ui-v2/README.md)을 기본 이미지 생성 도구로 제작했다. 이 새 세 화면의 표시 순서가 최신 선택 번호다. 카메라 응시·현대 초상 질감을 배제하고 실제 공개 화면의 한지·먹갈색·붉은 포인트·여백을 참고한다. 참고 사진·이름·전기를 제품 자산으로 쓰지 않으며 생성 장면을 실제 역사 기록으로 주장하지 않는다. 앱 기능·계산/풀이·저장 결과·공유·가격은 변경하지 않았다. 선택 후 적용과 회귀 검증은 별도다.

## 2026-10-20 조선 기록 사진풍 2안 선택·김춘배 훈장

사용자가 최신 documentary-ui-v2의 2안을 선택하고 충청북도·서당·김춘배 같은 지역/이름을 요청했다. **충청북도 괴산의 서당 훈장, 김춘배 할아버지**로 설정한다. 괴산은 구현 시 보충한 창작 지역이며 역사적 인물의 출신/생애를 주장하는 자료가 아니다. 표시명은 김춘배 훈장, 인물 버전은 kim-chunbae-v1이다. 카메라를 보지 않고 책을 내려다보는 창작 사진·한지·먹갈색 UI를 web 앱에 적용했다. 실제 조선의 행정구역 표기를 재현한다는 뜻도 아니다.

[인물·제작 기록](../design/characters/joseon/chunbae-v1/README.md)과 [실제 구현 비교](../design-qa.md)를 따른다. 훈장은 안내 역할이며 계산·풀이 기준·점수·가격에 영향을 주지 않는다. 엔진 v5·문구 v2와 저장 결과/주문은 유지한다. 신규 기호 설명 공유만 chunbae-v1/kim-chunbae-v1을 고정하고 기존 tigers-v1 공개 스냅샷은 이전 그림을 계속 표시한다. prototype은 보존한다. 외부 서비스·챗봇·실결제·공개 배포를 추가하지 않는다.
