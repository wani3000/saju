## 전문가 감수 진행

1. 검토자에게 베타 범위와 계산 권장안을 먼저 전달한다. 궁합 점수와 일반 강약·합화 판단을 이번 설명판이 제공하지 않는 점을 확인한다.
2. 양식을 별도 비공개 작업 위치에 복사한다. 각 ID의 문장·근거·조건·예외를 확인해 `수정 없음 / 수정 필요 / 근거 부족 / 검토 불가`로 기록한다.
3. 수정 필요 항목에는 원문 위치, 잘못된 주장, 권장 표현과 영향 범위를 남긴다. 일부 후보만 성립한 조건이 확정 표현에 섞였는지 확인한다.
4. 개발자가 수정하고 해당 사례·경계·저장 버전 회귀 검사를 실행한다. 검토자가 수정 반영을 재확인한다.
5. 최종 대상 버전과 감수 범위, 남긴 제한, 미해결 항목을 기록한다. 전문가 서명은 실제 검토자의 기록이 있어야 한다. 자동 검사나 Codex 검토로 대체하지 않는다.

일반 강약·왕기·합화·점수를 추가하려면 출처별 조건 충돌의 처리, 충분조건, 미판정 경로와 관계 효과 근거를 별도 승인한다. 명조 판어를 상대방 가감점으로 바꾸지 않는다.

## 실제 사용자 세션

가상 생일·별명만 사용한다. 본인·지인의 실제 생일, 연락처, 로그인키·복구 코드·공유 토큰·결제키는 관찰 양식이나 공개 저장소에 기록하지 않는다. 원치 않으면 언제든 중단할 수 있음을 먼저 알리고, 녹화가 필요하면 별도 동의를 받는다. 외부 원격 참여는 접근 제한과 서버 정책 확인 후 시작한다.

첫 회차는 소규모 성인 참가자를 모집하고 큰 글씨가 필요한 사용자도 포함하도록 제안한다. 인원 수나 만족도만으로 통과시키지 않는다. 진행자는 버튼 위치나 정답을 먼저 설명하지 않고 다음을 관찰한다.

1. 시작 화면에서 범위·저장 안내를 찾고 가상 내 정보와 상대 정보를 입력한다.
2. 정보를 수정하고 새로고침한 뒤 이어간다. 확인 체크가 자동으로 살아나지 않는지 확인한다.
3. 결과를 본 뒤 **기준 오행, 합·충, 대화 제안이 각각 무엇을 뜻하는지** 자신의 말로 설명한다.
4. 공유 미리보기에서 공개되는 별명·대화 주제를 설명하고, 링크를 만든 뒤 철회한다. 실제 이름을 공개 별명으로 입력하면 노출된다는 점도 확인한다.
5. 저장 결과로 돌아가 새 계산·재결제가 없는지 확인한다. 마지막으로 가상 계정을 삭제한다.
6. 양식의 다섯 질문을 묻고 실제 답변·도움 필요 여부·막힌 위치를 기록한다. `facilitatorExpected`는 진행자용이며 참가자에게 먼저 보여주지 않는다.

입력 자동 저장, 기호와 관계 예측의 구분, 공개 범위·삭제를 잘못 이해했다면 출시를 보류하고 문구/흐름을 수정한 뒤 새 세션으로 재확인한다. 수행하지 못한 단계는 `not-observed`로 남기고 성공 처리하지 않는다. 보조기기 전체 접근성 검수와 자동 확대 검사는 실제 사용자 관찰과 별도다.

## 기록과 재현

공개 저장소에는 빈 양식과 비식별 기술 수정만 둔다. 실제 검토 기록은 접근 제한된 별도 보관 위치에서 관리한다. `.local-review/`는 실수로 Git에 추가하지 않도록 제외돼 있지만 암호화·접근 제어를 제공하지 않는다.

```sh
node tools/prepare-launch-review.mjs --check
```

이 명령은 자료 해시·양식·출시 조건 연결의 재현만 검사한다. 원본이나 범위가 바뀌면 문서를 재검토한 뒤 `--check` 없이 다시 생성한다. 실제 참가자나 전문가 기록이 추가됐으면 먼저 기존 출시 보고서와 승인 근거를 대조해야 하며, 도구가 자동으로 승인을 붙이지 않는다.
