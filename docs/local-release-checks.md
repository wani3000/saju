# 사용자 흐름·보안·출시 전 자동 점검

2026-10-19. 점수 없는 로컬 비공개 베타의 입력→결과→공유→복구·삭제를 보강했다. [베타 범위와 승인 조건](beta-scope-and-quality.md)은 그대로 유지한다. 아래 검사는 공개 배포나 실결제를 승인하지 않는다.

## 수정한 동작

- 새로고침 후 저장된 입력 단계, 결과, 공유 미리보기로 돌아온다. 화면 복귀 정보는 탭의 `sessionStorage`에 버전·화면명·내부 식별자·수정 복귀 여부만 저장한다. 생일·이름·공유 토큰·복구 코드·동의 여부는 저장하지 않는다.
- 서버가 돌려준 현재 보관함에 해당 결과·대기 작업이 있을 때만 복귀한다. 환불·삭제되었거나 다른 보관함의 결과 식별자는 홈으로 돌린다. 입력 단계 복귀에도 서버 초안의 두 사람 식별자가 일치해야 한다. 저장 전 입력의 완전한 복원을 보장하지 않으며 “입력을 저장했어요” 이후의 서버 초안이 기준이다.
- 확인 화면에서 내 정보나 상대 정보를 수정하면 저장 후 확인 화면으로 바로 돌아온다. 정보를 바꾸거나 새로고침하면 저장 동의를 다시 확인한다. 복귀만으로 계산·주문·공유를 자동 실행하지 않는다.
- 로그아웃·계정 삭제·로그인 이관 성공 시 복귀 정보를 지우고, 코드로 보관함을 전환하면 이전 결과 선택·동의·공유 주소·공개용 별명을 초기화한다. 탭 저장소를 사용할 수 없어도 서버 저장과 기본 흐름은 계속 동작한다.
- 복구 코드 textarea와 설명 label을 명시적으로 연결했다. 코드를 브라우저 저장소나 새로고침 복귀 정보에 넣지 않는다.

## API 보강

공유 생성·철회, 작업 재시도, 주문 변경 경로가 뒤의 불필요한 경로까지 받아들이던 부분을 수정했다. 예를 들어 `results/{id}/shares/extra`는 새 공유를 만들지 않고 404를 반환한다. 주문의 모든 동작은 PG 설정을 읽거나 결제창을 준비하기 전에 현재 보관함의 소유권을 검사한다.

HTTP 검사는 다른 계정의 결과 조회·공유 생성·공유 철회·작업 재시도·주문 준비/승인/조회/취소/환불을 거절하는지 확인한다. 거절 후 원래 주문 상태와 활성 공유가 유지되는지, 계정 삭제가 이미 활성화된 공개 링크도 차단하는지 확인한다. 기존 CSRF·쿠키·공개 필드 제한·모의 중복 결제·복구 검증도 유지한다. 이 사례의 통과가 전반적인 보안 인증이나 침투 테스트 완료를 뜻하지 않는다.

## 재현 명령

저장소 루트에서:

```sh
npm ci --prefix web
npm exec --prefix web -- playwright install chromium
npm test --prefix web
npm run build --prefix web
npm run typecheck --prefix web
npm run test:journey --prefix web
npm run test:postgres --prefix web
python3 tools/check_docs.py
```

Linux CI의 브라우저 설치에는 `playwright install --with-deps chromium`을 사용한다. 브라우저 구성과 설치 방법은 [Playwright 설정](https://playwright.dev/docs/test-configuration)·[CI 안내](https://playwright.dev/docs/ci-intro)를 참고했다. 패키지는 개발 의존성 `@playwright/test@1.64.1`로 고정했다.

`test:journey`는 빌드를 먼저 요구한다. 실행할 때 임시 디렉터리에 빌드를 복사하고 빈 PGlite DB와 임의 포트의 `127.0.0.1` 서버를 만든 뒤, HTTP 검사와 320px·390px 브라우저 검사 8개를 실행한다. 기존 4180 서버나 개발 DB를 재사용하지 않는다. `.env` 파일을 읽지 않고 OS 실행에 필요한 환경 변수만 전달한다. 외부 DB·인증·PG 키는 상속하지 않으며 연구 모드·모의 결제로 고정한다. 실제 외부 주소를 대상으로 테스트를 돌리는 진입점은 제공하지 않는다.

실패하면 0이 아닌 종료 코드를 반환하고 다음 브라우저 사례를 중단한다. 브라우저 보고서·실패 추적과 합성 스크린샷은 Git 제외 경로 `web/test-results/`에 남긴다. 임시 서버·DB는 종료 후 정리한다. 보고서에는 테스트용 세션과 공유 토큰이 포함될 수 있으므로 일반 공개 자료로 올리지 않는다. CI는 이 검사를 매 push/PR에서 실행한다.

## 검증 결과와 복구 절차

- 웹 단위·서비스 검사 77개, 타입·빌드·문서 검사, 확장 HTTP 여정 및 모바일 8사례를 통과했다. 외부 DB를 가리키는 무효 URL·운영 모드·NICEPAY 설정을 부모 프로세스에 합성으로 넣어도 검사 서버는 이를 상속하지 않고 통과했다.
- 임시 PostgreSQL 17 클러스터에서 12개 동시 무료 요청, 작업 임대·중복 승인·환불 경쟁·익명 role 차단·실행 role DDL 차단을 재검증했다. 백업을 별도 DB에 복원하고 기존 결과 스냅샷 일치를 확인했다. 실제 운영 백업이나 운영 장애 복구를 수행한 것은 아니다.
- 서비스 배포 전에는 이 명령들과 [운영 준비](09-quality-operations.md)의 인증·PG 실제 왕복, 접근 제한, 로그·보존·삭제 정책을 별도 staging에서 확인해야 한다. 운영 오류 시 앱은 이전 버전으로 되돌리고 DB의 파괴적 역마이그레이션은 자동 수행하지 않는다. 결제 미확정 상태는 재결제보다 상태 조회·대사를 먼저 수행한다.

브라우저 8사례는 입력 검증·수정/복귀, 저장 실패/재시도, 결과 새로고침·근거·공유/철회, 로그아웃·코드 복구·삭제를 각 폭에서 검사한다. [상세 QA와 화면](../web/qa.md)에 관찰 결과를 기록한다. 실제 사용자 이해도·보조기기 전체 접근성·명리 전문가 감수·운영 성능은 아직 미완료다.
