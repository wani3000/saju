# 출시 후보 v1: 확인된 기호 풀이 선정과 앱 연결

2026-10-19. 사용자 요청에 따라 출시용 규칙 선정 → 풀이 작성 → 앱 연결을 순서대로 진행했다. 첫 후보 버전은 `source-observations-copy-v1`이다. 범위는 원전 정의를 설명하는 입력별 기호 비교와 관계별 대화 제안이다. 운영 계산·명리 해석·점수의 승인 상태를 올린 것은 아니며 앱은 연구 모드를 유지한다.

## 채택과 보류

| 항목 | v1 결정 | 근거·적용 범위 |
|---|---|---|
| 일간의 오행 | 채택 | 기존 『연해자평』 1926년 판본 PDF 23쪽의 천간 배속. 일간 한 글자의 분류로만 설명 |
| 천간 합 5쌍 | 기호 관찰로 채택 | PDF 23쪽의 짝 정의. 두 사람의 관계에 대한 예측·합화와 구분 |
| 지지 육합 6쌍 | 기호 관찰로 채택 | PDF 25쪽의 짝 정의 |
| 지지 육충 6쌍 | 기호 관찰로 채택 | PDF 26쪽의 짝 정의. 합과 동시 관찰되면 상쇄하지 않음 |
| 비교 위치 | 연·월·일 | 양쪽에 공통인 세 기둥만 비교. 시각을 알아도 이번 비교에는 시주를 넣지 않음 |
| 후보가 여러 개인 경우 | 전체 후보 공통 사실만 채택 | 일부 후보의 일치·비율을 확정 해석·확률로 만들지 않음 |
| 시간 모름·역사 시계·절기 경계 | 상태 안내 채택 | 시각 보충 금지, 후보 공통이라는 사실과 계산의 최종 승인을 구분 |
| 관계별 대화 주제 | 편집 제안으로 채택 | 친구·가족·연인·동료 각 1개. 생일에서 추론한 성격·관계 강약과 구분 |
| 사령·강약·중화·합화·파상·자조 | 사용자 풀이에서 보류 | 원전 간 상충과 일반 판정 기준이 남아 있음. 기존 연구 모듈은 보존 |
| 성격·관계 성공·길흉 예측 | 보류 | 관찰된 기호만으로 도출할 검토된 추론 규칙 없음 |
| 궁합 점수·지도 거리 순위 | 보류 | 점수는 null. 지도는 저장된 사람을 여는 보관함으로 사용 |

기계 판독 정책은 [selected-reading-policy.json](../research/validation/selected-reading-policy.json)이다. 원전의 17개 기호 정의 ID를 정확히 허용하고 전체 기둥을 점수처럼 세지 않는다. 채택은 이 설명 범위에 한정된다. 원전이 두 사람 사이의 성공·실패를 입증한다는 주장은 하지 않는다.

## 풀이 구성과 편집 감수

[풀이 생성기](../research/validation/selected-reading.mjs)는 검증된 연구 프로필 두 개와 관계 유형을 받는다. 이름·원본 날짜·UTC·임의 사용자 필드는 풀이 근거에 복사하지 않는다.

1. **두 사람의 기준 오행:** 두 일간 오행이 각각 하나로 확인될 때 해당 배속을 설명한다. 사주 전체 비율로 확대하지 않는다. 후보가 다른 오행을 포함하면 미확정 문구를 사용한다.
2. **함께 살펴볼 기호:** 입력 후보 전체에 공통인 천간 합·지지 육합·지지 육충 종류를 모두 요약한다. 없는 경우도 관계 불량·중화 등으로 해석하지 않는다.
3. **비교 근거와 확인 범위:** 위치·기호·출처 쪽을 제공한다. 기호 ID와 위치 이름을 기준으로 최대 6개를 표시하고, 잘린 항목 수를 안내한다. 순서는 중요도나 점수가 아니다. 요약은 표시 상한 이전의 모든 공통 종류를 사용하므로 충이나 합이 화면 상한 때문에 사라지지 않는다.
4. **오늘의 작은 제안:** 관계 유형별 대화 주제를 제공하고 생일 기반 성격 풀이가 아님을 표시한다.

검토자는 Codex이며 범위는 기존 원전 정의의 재사용, 쉬운 문장 편집, 조건 누락·단정·기술 검증이다. 명리 전문가의 승인이나 실제 사용자 이해도 검증으로 표시하지 않는다. [9사례 문장 보고서](../research/validation/reports/selected-reading-drafts.md)에 네 관계 유형, 공통 짝 없음, 후보 의존, 합충 공존, 시간 모름, 절기 경계를 기록했다. 구조 예시는 실제 출생 명조가 아닌 합성 fixture다.

## 앱 연결과 결과 보존

신규 비교는 이 버전 ID를 저장한다. worker는 요청자가 보낸 점수나 나중의 초안 대신 **해당 비교에 저장된 계산표·관계 유형·풀이 버전**을 사용한다. 버전을 찾지 못하거나 계산표가 맞지 않으면 최신 문구나 일반 예시로 대체하지 않고 기존 실패 복구·무료권 반환 경로로 종료한다.

`example-copy-v1`과 `example-copy-v2`는 원문과 로더를 그대로 보존한다. 기존 v3/v4 계산을 가진 대기 작업도 기존 풀이 버전으로 처리한다. 이미 저장한 결과·구매·공유는 다시 생성하거나 최신 버전으로 바꾸지 않는다. 같은 사람 쌍의 기존 결과 재열람도 버전 변경 때문에 재과금하지 않는다. 새 규칙을 기존 결과에 강제로 적용하는 새로고침 기능은 추가하지 않았다.

웹의 제목·카드·상세 확인 영역은 기존 호랑이 화면 안에서 수정했다. 새 결과에는 입력별 설명, 범위·불확실성 및 근거를 표시한다. 이전 결과를 열면 이전 예시 안내를 유지한다. 지도 배치는 보관함 위치로 설명하며 친밀도 순위로 표시하지 않는다.

계산과 기호 비교는 서버 전용 번들이다. 원전 JSON 명세와 정책을 빌드 때 포함하며 요청 처리 중 외부 문헌·API에 의존하지 않는다. 클라이언트에서 재계산하거나 임의 가중치를 실행하지 않는다.

## 공개 공유

새 풀이의 원본 기호 설명·위치·출처·경계 상태는 비공개 결과에 남긴다. 공개 카드에는 공개용 별명, 관계별 대화 제안과 별도의 일반 문구만 넣는다. 공유 미리보기와 서버 저장은 같은 `publicCard` 투영 함수를 사용한다. 이전 예시 카드의 공개 문구와 구조는 유지한다.

## 검증과 남은 출시 조건

연구 검증은 17쌍 양방향 정의, 입력별 문구 변화, 후보 의존 제외, 시주 제외, 합충 공존·표시 상한, 관계 유형 변경, A/B 교환, 개인정보 제외, 달력/시계 플래그, 음양력 대응·결정성, 보고서 재현과 미승인 상태를 확인한다.

웹 검증은 신규 생성, 저장된 계산표 기반 처리, 공유 투영, 이전 v1/v2 문구·v3/v4 계산 보존, 재과금 방지, 손상된 계산표 실패 복구를 확인한다. HTTP·브라우저 검증은 입력 → 신규 결과 → 범위 확인 → 공개 미리보기·공유 → 재열람 경로를 따른다.

```sh
node research/validation/audit-selected-reading.mjs --check
node research/validation/audit-selected-reading.mjs --release-check
pnpm --dir research/validation test
npm test --prefix web
npm run typecheck --prefix web
npm run build --prefix web
python3 tools/check_docs.py
```

`--release-check`는 운영 계산·명리 해석 승인이 pending이므로 종료 코드 2다. 외부 Supabase·카카오·NICEPAY 왕복, 실제 사용자·보조기기 검증, 운영 정책·환경 구성과 최종 공개 배포는 후속 단계다. 이번 첫 후보를 신강·신약·합화 판정이나 완성된 유료 궁합 상품으로 표시하지 않는다.

실행 결과: 연구 169개·웹 72개 테스트, TypeScript·빌드·문서 검사, 9사례 및 이전 보고서 재현, HTTP 전체 여정 통과. 별도 임시 DB와 브라우저 context에서 320px·390px 입력·결과·근거·공유·재열람을 확인했다. [화면과 검증 범위](../web/qa.md)의 2026-10-19 출시 후보 기록을 따른다.
