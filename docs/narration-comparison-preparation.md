# 설명 모델 비교 준비 — API 재인증 전

2026-10-22. 사용자가 GPT-6 Luna와 GPT-5 nano를 실제 비교하고 더 나은 모델을 붙이도록 요청했다. 새 API 키 생성·데스크탑 저장은 허용했으나 OpenAI Platform 연결의 재인증이 막혔으며 **키 생성/저장/실제 API 호출/품질 평가/모델 선택은 모두 미실행**이다. 사용자가 재인증을 나중에 하고 다른 작업부터 진행하도록 요청해, 연결 없이 검증 가능한 준비를 구현했다.

## 완료한 범위

- [입력·출력 계약](../web/src/server/narration-contract.ts): 공개 v8의 확인된 전체 기둥 근거와 개인별 장점/주의점/필요한 배려, 기존 양방향 도움 원고를 같은 묶음으로 전달한다. 사람이 달라도 같은 로컬 근거 ID를 쓰므로 `me:`/`other:` 구분을 붙였다. 기존 계산의 `a`/`b` 경계·시계 보류 표시를 함께 변환한다.
- 원 생년월일, 이름, 사용자 ID, 전체 차트 JSON은 입력에 넣지 않는다. 이 데이터 최소화는 완전 익명 보장이 아니다. 모델에게 없는 시주·후보의 글자·미확정 강약/합화·점수를 생성시키지 않는다. 연구 종합 v2의 보류 판단도 승인하지 않는다.
- [서버 후보 생성기](../web/src/server/narration-candidate.ts): OpenAI Responses API, JSON Schema, `store:false`, 고정 호스트, 60초 제한, 요청 크기/출력 상한을 사용한다. 두 후보만 허용한다. Luna는 `reasoning.effort:none`, nano는 공급자 기본 설정을 사용하며 설정 차이를 실행 기록에 남긴다. 온도나 두 모델에 공통이라고 확인하지 못한 설정을 억지로 넣지 않는다.
- 형식, 필수 문단, 관계 종류, 원본 입력 해시, 사람별 근거 범위, 중복/누락을 검사한다. 범위 밖 판어·궁합 점수·비연인 결과에 섞인 연애 어휘·링크/HTML 일부도 탐지한다. 문장 의미의 일치나 도움의 주체를 이해하는 검사는 아니다. 근거 ID를 맞게 복사하면서 틀린 설명을 하는 경우는 별도 감수로 찾아야 한다.
- 시간 초과/거절/불완전 JSON/검증 실패는 실패 코드로 남기며 원문 공급자 오류나 키를 출력하지 않는다. 자동 재시도/다른 모델 호출/기존 결과 갱신은 없다. 성공 후보도 `semanticReview:pending`, `productionApproved:false`다.
- [합성 입력](../web/scripts/narration-cases.ts) 40쌍 × 네 관계 =160건. 같은 날의 다른 시간 입력, 시간 모름, 절기 경계, 과거 시계 검토를 포함한다. 새 독립 명리 정답 사례를 발견한 것으로 세지 않는다.
- [실행 도구](../web/scripts/compare-narration.ts): 기본은 오프라인. 실제 호출은 명시적 live 모드·키·양수 예산이 모두 있어야 한다. 호출 전 비용 여유분을 예약하고 호출 수/출력 상한을 제한한다. 이 예산은 공급자가 강제하는 결제 상한이 아니라 고정 요금 가정의 보수적 실행 중단 기준이다. 응답/타임아웃에서 usage가 없으면 비용 미확인 횟수도 남긴다.
- A/B 표시는 사례마다 뒤집어 순서 편향을 줄이며 같은 모델이 A로 먼저 나오는 수는 86/74다. 모델 대응표와 모델명을 가린 원고를 따로 저장한다. 미완료 감수 양식의 점수는 null이다. [집계기](../web/src/server/narration-review.ts)는 완료한 감수만 집계하고 중복/실패한 결과의 감수를 거절한다. 평균을 내도 자동으로 승자를 선정하지 않는다.

**앱·작업 처리기·공개 preview는 후보 생성기를 가져오거나 실행하지 않는다.** 기존 v8, 저장 결과, 공유 카드와 체험판을 유지했다. 서버 후보 모듈 준비는 서비스에 모델 적용을 끝냈다는 의미가 아니다. 브라우저에서 호출할 공개 AI API 경로와 비밀 키를 만들지 않았다.

## 오프라인 확인

[집계 결과](audits/narration-offline-readiness.json)를 생성했다. 네 관계 각40건, 시간 모름 포함116건(모름0명44건/1명56건/2명60건), 절기 검토4건, 시계 검토12건이다. 이 값은 입력 준비의 소프트웨어 범위이며 모델 정확도나 전문가 감수가 아니다. 실제 모델 출력은 하나도 없다.

- 새 계약·어댑터·감수 집계 회귀 검사10개, 웹 전체142개 통과.
- 타입 검사와 Next.js 빌드 통과. 화면이나 공개 API 경로 변경이 없어 UI 재배포는 하지 않았다.
- 테스트 응답은 네트워크를 흉내 낸 고정 자료다. 실제 모델의 한국어 품질 비교 결과로 사용하지 않는다.

## 재인증 후 실행 순서

`web` 폴더 기준. 키는 사용자 승인된 안전한 설정 경로에서 주입하며 아래 명령에 값을 넣지 않는다.

```sh
# 준비만: API 호출 없음, 결과는 Git 제외 web/.data 아래 새 디렉터리에 보관
npm run narration:prepare
npm run narration:audit

# 재인증/키 설정 후 소규모 연결·품질 확인: 16건 × 두 모델, 최대32회 시도
npm run narration:compare -- --limit=16 --max-cost-usd=0.30

# 첫 표본을 검토한 뒤 전체: 별도 실행 폴더, 최대320회 시도
npm run narration:compare -- --limit=160 --max-cost-usd=3

# 생성된 review-template.json의 감수를 채운 뒤 집계
npm run narration:summarize -- .data/<실행폴더> .data/<실행폴더>/review-template.json
```

원고/usage/시간은 `results.jsonl`, 모델을 가린 원고와 기존 v8은 `blind-review.jsonl`, 모델 대응표는 `blind-key.json`에 기록된다. 실패도 기록하고 동일 폴더를 덮어쓰지 않는다. 오프라인 요청 UTF-8 바이트 수는 실측 토큰 수가 아니다. 실행 요금표와 9,000 총 출력 토큰 상한은 [기존 4,000입력+2,000출력 가정](openai-narration-review.md)의 예시 가격과 다르므로 이전 비용을 실제 측정값으로 인용하지 않는다.

## 원고 감수 기준

생성된 모델의 자기평가만으로 통과시키지 않는다. 우선 모델 이름을 가린 채 같은 입력의 원고를 기존 v8 및 허용 근거와 나란히 대조한다. 각 항목은 1~5점이며, 1은 큰 수정 필요, 3은 사용 가능하나 수정 필요, 5는 수정이 거의 필요 없는 상태다. 결과 문장 인용과 판단 이유를 함께 기록한다.

| 항목 | 대조할 내용 |
| --- | --- |
| 훈장 말투 | 쉬운 하게체인지, 고어/명령/반복 인사가 과하지 않은지, 인용 대화는 자연스러운지 |
| 구체성 | 어떤 상황에서 누가 무엇을 해볼지 이해되는지, 예시를 실제 과거처럼 만들지 않았는지 |
| 개인·궁합 일치 | 같은 사람의 장점과 주의점이 같은 뿌리인지, 개인의 필요와 궁합의 도움 방향이 같은지 |
| 근거 충실성 | 없는 성향/기둥/강약/합화/부족함을 추가하거나 보류를 확정하지 않았는지 |
| 반복 절제 | 같은 원고를 여러 제목에 복사하지 않았는지, 줄이면서 핵심 의미를 잃지 않았는지 |

사람 뒤바뀜·생일/기호 변경·보류 확정·관계 유형 혼입·검증되지 않은 판정은 치명 오류로 기록한다. 이런 오류가 있는 원고를 높은 평균 점수로 덮지 않는다. 모델 선택 시 영역별 결과, 오류 사례, 지연 p50/p95, usage와 비용을 함께 본다. 표본에서 오류가 없더라도 무오류 보장이나 사주 적중률로 발표하지 않는다.

모델 선정 뒤에는 새 풀이 버전/스냅샷, 호출 소유권과 중복 방지, 외부 처리 안내, 호출 한도, 실패 시 기존 v8 표시, 실제 결과 화면 연결과 테스트를 이어간다. 미감수 후보를 공개하는 우회 플래그는 이번에 만들지 않았다.

## 공식 근거

[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-5 nano](https://developers.openai.com/api/docs/models/gpt-5-nano). Structured Outputs는 출력 모양을 제한할 수 있지만 문장의 사실성까지 보증하지 않는다. 계정별 두 모델 접근 여부는 아직 확인하지 못했다.
