# 2026-10-14 역사적 출생 시각 계산 경로 검증

## 변경

연·월주는 고정 IANA Asia/Seoul 자료로 변환한 UTC 순간을 엔진 core에 전달한다. 일·시주는 기록된 현지 시계와 자정 기준을 유지하는 연구 정책이다. 경도·균시차 보정은 적용하지 않는다. 정책 버전은 research-civil-midnight-v3이며 productionApproved=false다.

기존 엔진 wrapper는 옵션을 생략하면 모든 시각을 UTC+9로 해석했다. 새 어댑터는 원본 소스를 수정하지 않고 고정 커밋의 computeFourPillars를 별도 빌드하여 두 시계를 명시적으로 전달한다.

시간 모름은 실제 현지 날짜에 해당하는 UTC 구간을 모두 계산한다. 시계가 앞당겨진 23시간 날짜, 되돌아간 25시간 날짜와 자정이 존재하지 않는 날도 처리한다. 구간 끝과 내부 절입 경계 양쪽을 탐색해 후보를 보존하며 출생 시각을 정오 등으로 확정하지 않는다. 알고 입력한 시각이 누락되거나 중복이면 기존과 같이 오류를 반환한다.

## 검증 근거

| 범위 | 확인 결과 | 한계 |
|---|---|---|
| 전체 자동 테스트 | 29개 통과 | 운영 승인 아님 |
| KASI 파생 738일 | 어댑터의 일주 및 대응 음력 입력 동등성 통과 | 기존 2023~2024 월초 자료에서 전개한 사례 |
| KASI 절입 앞뒤 48개 입력 | 어댑터의 월지 통과 | 분 단위 기대값, 과거 연도 천문 정확도 증명 아님 |
| 고정 IANA 1,918개 사례 | UTC 후보와 날짜 구간 양쪽 대조 통과 | 같은 IANA 자료를 Python/JS 경로로 대조 |
| 1954 UTC+8:30, 1988 서머타임 절기 | 같은 실제 순간의 연월주 일치, 현지 일시주 유지 | 후보 엔진 자체 절입 시각 사용: 전달 경로 시험 |
| 자정·시간 모름·DST | 자정의 일주 변경, 누락·중복 시각 오류, 23/25시간 날짜 구간 및 시주 null 확인 | 정책 선택 자체의 명리 감수는 별도 |

1954-04-05 16:30과 1988-06-05 21:14 같은 경계 사례에서 이전 wrapper와 월주 차이를 재현했다. 위 절입 시각은 후보 엔진에서 얻었으므로 결과의 천문학적 정답을 독립 확인한 것으로 취급하지 않는다.

## 재현과 출처 보존

- `node research/validation/restore-engines.mjs`: 엔진이 없으면 정확한 commit을 복원한다. 기존 checkout의 다른 HEAD나 변경 파일은 덮어쓰지 않고 오류로 중단한다.
- `node research/validation/restore-engines.mjs --check`: commit·변경 여부·패키지 버전·LICENSE 확인만 한다.
- build.mjs는 빌드 전에 위 검증을 수행한다.
- 원본 MIT 고지는 research/validation/licenses에 보존한다.
- .github/workflows/research-validation.yml에 고정 런타임·의존성 설치, 문서 검사, 빌드, 테스트를 구성했다. CI의 실제 실행 결과는 해당 GitHub Actions run을 확인한다.

## 남은 운영 조건

과거 연도 절입의 독립 자료 교차 확인, 넓은 출생 연도 음양력 자료 검증, 현지 시계/진태양시 및 일 경계 정책 감수, 엔진 배포 패키지와 소스 대조, 궁합 규칙과 풀이 감수가 남아 있다. 기존 후보 엔진 비교 보고서의 실패나 99건 시간대 불일치 보고서는 원본 엔진에 대한 기록으로 유지한다.
