# 스테이징 앱 DB 백업의 격리 로컬 복원 검증

2026-10-22. 전용 서울 Supabase `chunbae-staging`의 **public 앱 스키마 21테이블**을 실제로 백업하고, 소켓만 여는 임시 로컬 PostgreSQL 17에 복원했다. 전체 테이블 데이터, 스키마·제약·인덱스·RLS·테이블/스키마/기본 ACL이 일치했다. 실제 프로필과 세션을 포함한 원문·해시는 출력하거나 저장소에 보관하지 않았다.

## 실행과 보호

`web/`에서 실행한다. 관리자 설정은 기존 Git 제외·권한600 bootstrap 파일만 읽는다. 관리자 자격을 Vercel에 올리거나 앱 실행 역할을 확대하지 않는다.

```sh
npm run test:hosted-restore -- \
  --settings .env.staging.local \
  --bootstrap .env.supabase-bootstrap.local \
  --project nwicejxousubxiczwwkb \
  --private-local-copy
```

- 연구 모드·명시적 원격 검사 허용·프로젝트 일치·서울 session pooler 관리자/transaction pooler 앱 계정·verify-full/지정 CA를 먼저 검사한다. 다른 지역/대상·추가 연결 옵션·TLS 완화는 거절한다.
- 원격 관리자 연결과 pg_dump는 기본 읽기 전용이다. `REPEATABLE READ READ ONLY`에서 내보낸 동일 snapshot으로 데이터 지문과 덤프를 비교한다. `pg_dump` 경고는 통과로 무시하지 않는다. 이 절차는 작은 전용 스테이징(앱 테이블 합계64MiB 미만)만 허용한다.
- 인증/스토리지 스키마와 함수/확장·역할 비밀번호는 복사하지 않는다. 현재 public에 함수/확장이 있으면 중단한다. 원격 역할 이름만 로컬의 비로그인·비관리자 자리표시자로 만들고 앱 역할 상속을 로컬에서 재현한다.
- 실제 개인 기록을 포함할 수 있으므로 `--private-local-copy`를 명시해야 한다. 임시 디렉터리는700, 덤프/복원 목록은600이다. 복원은 이 명령이 만든 로컬 소켓 DB만 사용하며 외부 작업·결제·세션을 재실행하지 않는다.
- 정상/예외 종료 모두 연결 종료→클러스터 정지→임시본 제거를 수행한다. 정리 실패는 종료1/`LOCAL_CLEANUP_REQUIRED`로 처리한다. 강제 종료·전원 중단까지 자동 파기를 보장하지 않으며 재실행 전 임시 폴더를 확인해야 한다.
- 출력은 고정 상태·검증 여부·테이블 수·현재 health 사유·소요 시간뿐이다. 비밀값·행·사용자 식별자·원문 SQL 오류·해시는 출력하지 않는다.

복원 후 제한 `saju_server` 역할에서 모든 테이블의 같은 데이터를 읽고, DDL과 마이그레이션 원장 수정이 거절되는 것을 확인했다. 익명 역할은 테이블 권한 거절 또는 RLS의0행으로 차단되며 삽입도 거절된다. 현재 원격 health는 별도 읽기 전용 조회에서 `ok`, 사유 없음이었다. 이는 지속 감시나 작업 큐 비움 보장이 아니다.

## 발견한 불일치와 수정

처음 임시 DB의 `public` 스키마를 지웠다가 복원하니 initdb의 기본 `PUBLIC USAGE`가 사라졌다. pg_dump의 ACL 변경분은 이 기본값을 전제로 하므로 데이터/테이블 권한은 같아도 스키마 ACL 한 항목이 달랐다. initdb 스키마를 유지하고 복원 목록에서 **스키마 생성 항목 하나만** 제외했다. 스키마 ACL·소유자와 나머지 앱 객체는 복원/대조한다. 원격 권한을 바꾸거나 검사에서 ACL을 제외해 통과시키지 않았다. 시각 표현은 양쪽 UTC로 고정했다.

익명 테이블 조회는 호스팅 권한에 따라 SQL 권한 거절 또는 RLS0행일 수 있다. 둘 모두 차단으로 인정하되 한 행이라도 보이면 실패한다.

## 실제 결과와 남은 범위

최종 실제 실행: 21테이블·동일 snapshot·TLS·읽기 전용·데이터/스키마/권한 대조·제한 역할·익명 차단 통과, **4초**, 임시 복원본 제거 확인. 반복 결과는 실행 시점에 따라 달라질 수 있다. 웹157개와 타입 검사도 통과했다.

이 검증은 **호스팅 앱 데이터 → 격리 로컬 복원**이다. Supabase `auth.users`/제공자 키·비밀번호·스토리지 객체·카카오/결제사 상태는 포함하지 않는다. 다른 Supabase 프로젝트에 대한 전체 재해 복구, 장기 백업 저장/암호화·접근자·보관/삭제 기간·RPO/RTO 승인, 자동 백업/운영 스케줄러·알림은 아직이다. 외부 로그인 복구까지 완료했다고 표시하지 않는다. 원격 DB에 복원/마이그레이션/삭제를 실행하지 않았다.

일반 합성 데이터의 세션·유료 권한·공유 철회·작업 한 번 재개 검사는 기존 `test:postgres`로 별도 검증한다. 실제 이용자의 세션을 복원본에서 사용하지 않는다.

구현 기준: [PostgreSQL pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html), [snapshot 동기화](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION). 현재 [서버 테스트](https://chunbae-staging.vercel.app/)의 앱 화면/계산/풀이/스키마/배포 버전은 이번 운영 도구 추가로 바꾸지 않았다.
