# 캐릭터 적용 설계 초안

기준일 2026-10-14. 다른 PC의 bfa9bd5에서 작성한 사용자 요구 기반 설계를 현재 main에 통합했다. [사주햄찌 공개 흐름 분석](sajuham-audit.md)과 [새 캐릭터 시작 화면 3안](../design/characters/README.md)은 이 저장소에서 이미 작성했다. 외형·브랜드·시안은 아직 선택되지 않았으며 실제 앱과 운영 자산은 미구현이다. 이 문서는 화면별 역할과 표시 데이터의 설계다.

## 목적

캐릭터는 두 사람을 쉽게 구분하고 입력부터 결과까지 안내한다. 핵심은 큰 글씨와 짧은 행동이다. 캐릭터 도감·뽑기·꾸미기·등급·별도 구매 기능은 MVP 범위에 추가하지 않는다.

## 화면별 적용

| 화면 | 캐릭터 역할 | 콘텐츠와 행동 |
|---|---|---|
| 시작 | 안내 캐릭터 1개 | 한 줄 설명, 첫 한 명 무료, 무료로 시작하기 |
| 내 정보 | 안내 캐릭터를 작게 표시 | 1단계 내 정보, 생년월일 입력. 캐릭터 선택 단계 추가 없음 |
| 상대 정보 | 내 캐릭터와 상대 캐릭터를 이름과 함께 표시 | 2단계 상대 정보, 가격은 버튼에 명시 |
| 입력 확인 | 두 이름과 날짜가 우선 | 장식으로 정보를 가리지 않음. 수정 링크 유지 |
| 계산 중 | 같은 두 캐릭터 | 두 사람의 궁합을 보고 있어요. 가짜 정확도·가짜 카운트다운 금지 |
| 결과 | 두 캐릭터가 나란히 등장 | 이름 → 요약 → 잘 맞는 점 → 차이 → 조언 → 공유 → 지도 |
| 관계지도 | 가운데 나, 주변 상대의 캐릭터 | 노드마다 이름. 탭하면 기존 결과. 같은 내용은 목록에도 제공 |
| 공유 미리보기 | 선택한 두 사람만 등장 | 공개용 별명과 풀이 확인. 다른 사람·전체 지도 제외 |
| 추가 유료 | 안내용 작은 캐릭터만 사용 | 추가 상대 1명 2,900원, 기존 결과 재열람 무료를 명확히 표시 |

## 외형 제작 기준

- 어른도 부담 없이 볼 수 있는 둥근 실루엣, 단순한 얼굴, 차분한 색을 목표로 한다.
- 원본 캐릭터와 이름·실루엣·표정·의상·색 조합을 복제하지 않는다.
- 안내용 기본 캐릭터 1개와 사람 구분용 변형을 최소 수량으로 설계한다. 정확한 종·수량·색은 시안 선택 후 확정한다.
- 상대마다 보조 색·작은 소품·이름을 조합해 구분한다. 색만으로 구별하지 않는다.
- 낮은 궁합의 상대도 동일한 품질과 친근한 표정으로 표시한다. 악당·울음·벌점 표시로 낙인찍지 않는다.
- 오행·띠·성별을 외형에 자동 배정하지 않는다. 필요하면 검증된 계산 근거와 별도 정책을 정의한 후 결정한다.
- 현재 기본안에서 캐릭터는 표시용이다. 캐릭터가 사주 계산·궁합 점수·결제 가격에 영향을 주지 않는다.

## 큰 글씨와 지도

본문 18~20px, 제목 28~32px, 버튼 높이 56px 이상을 유지한다. 캐릭터 때문에 텍스트 크기를 줄이지 않는다. 지도 노드는 클릭 영역 최소 48px을 목표로 하고 겹침과 실제 탭 동작을 검증한다.

노드의 궁합 거리는 [지도 설계](08-map-sharing.md)의 q→반경 산식을 따르는 계획이다. 궁합 규칙의 운영 감수와 산식 구현·검증은 아직 미완료다. 일러스트 크기·각도·표정은 점수를 바꾸지 않는다. 충돌은 각도·라벨 배치·페이지 또는 목록으로 해결한다. 인원 증가 때문에 노드와 글씨를 작게 축소하지 않는다. ‘가까울수록 궁합이 잘 맞아요. 실제 친밀도와는 달라요.’를 지도 설명 초안으로 쓴다.

노드의 접근성 이름은 별명과 결과 보기 행동을 전달한다. 이름을 반복하는 장식 이미지에는 빈 대체 텍스트를 적용한다. 움직임 줄이기 설정을 존중하고 필수 정보는 정지 화면에서도 확인 가능하게 한다.

## 데이터와 렌더링

사주 계산 정보와 캐릭터 표시 정보를 분리한다. persons에 display_avatar_key, display_avatar_variant, avatar_catalog_version을 추가하는 논리안을 둔다. 이 값은 서버가 승인한 카탈로그 키이며 사용자 임의 이미지 URL이나 SVG 문자열을 저장하지 않는다.

- 첫 생성 때 표시용 기본값을 할당하고 저장한다. 날짜 문자열 해시로 외형을 정하지 않는다.
- 동일한 생일의 서로 다른 사람은 별개의 person이며 다른 표시값을 가질 수 있다.
- 새로고침·상대 추가 때 기존 사람의 외형을 무작위로 바꾸지 않는다.
- 별명·캐릭터 변경은 계산·결과 재생성·과금 없이 표시 정보만 변경한다.
- MVP에서는 외형 자동 배정만 제공하고 꾸미기 화면은 추가하지 않는 기본안을 둔다.
- share_links.public_snapshot에는 공유 생성 시 두 사람의 승인된 표시 키·카탈로그 버전을 복사한다. 기존 공유는 이후 프로필 변경으로 조용히 바꾸지 않는다.
- 카탈로그의 구버전 자산을 보관하고 키 누락·이미지 실패에는 공통 기본 캐릭터와 이름을 제공한다.
- 유료 결과의 해석 스냅샷은 표시용 외형 변경과 무관하게 유지한다.

## 자산 납품 기준

외형 선정 후 자산별 용도·크기·파일명·버전·제작 출처·이용 조건을 design/characters에 기록한다. 정적 이미지를 우선하고 결과용과 지도용은 각 크기에서 알아보기 쉬운 별도 구도를 제작한다. 검증하지 않은 작은 크기 자동 축소나 sprite 임의 잘라쓰기는 피한다. 파일 용량 예산은 실제 화면 성능을 측정하며 확정한다.

## 순차 작업

1. 확보한 사주햄찌 홈 → 궁합 상세 → 로그인 캡처와 분석을 재사용한다. 로그인 이후 입력·결과·공유·충전은 미검증이다. 다른 PC의 접근 실패는 이 캡처를 무효화하지 않는다.
2. 기존 design/concepts와 새 design/characters 시안을 구분한다. 새 시작 화면 3안은 이미 생성했으므로 중복 제작하지 않는다. 사용자 선택은 아직 없다.
3. 선택한 방향을 큰 글씨 결과·관계지도 화면과 사람 구분용 캐릭터 변형으로 확장한다. 시작 화면 이미지는 결과·지도 시안의 완료 근거가 아니다.
4. 선택한 방향의 캐릭터 자산·디자인 토큰·클릭 흐름을 검증한다. P01의 남은 엔진 검증과 P02 조건을 확인하고 P03 합성 데이터 앱 골격을 진행한다. 연구 엔진을 운영 승인으로 간주하지 않는다.
5. P04에서 표시 필드와 카탈로그 허용 목록을 구현하고, P06에서 공유 표시 스냅샷·철회 및 지도·목록 동작을 검증한다.

## 검증할 사례

첫 상대 1명, 여러 상대의 비슷한 외형, 같은 별명, 같은 생일의 다른 사람, 긴 별명, 8명 이상 겹침, 이미지 실패, 200% 확대, 키보드 선택, 움직임 줄이기, 프로필 외형 변경 후 기존 공유 유지, 외형 변경 전후 궁합 점수·가격 불변을 확인한다. 실제 테스트는 구현 뒤 수행하며 이 문서는 완료 증거가 아니다.
