# 출시 준비 실행 순서와 운영 초안

2026-10-20. 로컬 설명판의 준비 문서다. 외부 서비스·운영 DB·공개 배포는 실행하지 않았다. 외부 인증·NICEPAY는 계정과 테스트 설정이 준비되면 진행한다. 실제 과금은 계속 차단한다.

후속 사용자 지시에 따라 실제 사용자 관찰은 건너뛰고 [1→3→4](launch-sequence-1-3-4.md)로 진행한다. 관찰0명과 빈 양식은 보존하며 사용자 테스트를 진행 차단 조건으로 다시 요구하지 않는다. [실행 목록](launch-preparation.json)은 다른7개 미완료 항목을 유지한다. 기존 연구 보고서의8개 미실시 항목은 기술 근거 상태 기록이며 실행 결정과 구분한다.

## 1. 로컬 후보 검증

현재 저장 결과와 계산/풀이 버전을 보존한다. 웹 단위·서비스 검사, 빌드·타입, 별도 임시 DB의 HTTP/브라우저 여정, 로컬 PostgreSQL 동시성·복원을 실행한다. [실행 안내](../web/README.md)와 [로컬 격리 검사](local-release-checks.md)를 따른다.

```sh
pnpm --dir research/validation test
node research/validation/audit-release-readiness.mjs --check
node tools/prepare-launch-review.mjs --check
npm test --prefix web
npm run build --prefix web
npm run typecheck --prefix web
npm run test:journey --prefix web
npm run test:postgres --prefix web
python3 tools/check_docs.py
```

`audit-release-readiness.mjs --release-check`의 현재 예상 종료 코드는 **2**다. 테스트가 통과해도 8개 출시 조건의 실제 승인이 생기지 않는다.

## 2. 외부 비공개 체험 준비

호스팅 담당자가 정해지면 별도 staging과 DB를 사용한다. 호스팅의 초대자 접근 제한을 먼저 구성하고 허용·비허용 브라우저에서 `/`, `/api/state`, 직접 결과 요청, `/s/...`, 인증·PG 반환 경로를 확인한다. 로그인 화면만 가리고 API/공유 URL이 열리는 상태는 접근 제한 완료가 아니다.

`ALLOW_REMOTE_TEST=true`는 개발 API의 로컬 제한을 해제하는 옵션이며 초대자 접근 제어가 아니다. 현재 공유 링크도 URL 보유자 열람 방식이다. 프록시·CDN·분석 도구·오류 수집에서 요청 URL의 공유 토큰·인증 코드·결제 반환값과 생일 본문을 기록하지 않도록 설정·검증한다. 운영용 HTTPS·쿠키·서버 권한/RLS·캐시 비공개 동작도 staging에서 확인한다.

외부 사용자 관찰은 접근 제한, 개인정보 안내와 문의 창구를 확인한 뒤 시작한다. 실사용 데이터는 CI fixture나 공개 저장소로 옮기지 않는다.

## 3. 준비 후 인증·결제 왕복

인증: Supabase/카카오의 정확한 redirect 설정 → 신규 연결 → 취소/만료 → 기존 보관함 전환·합치기 → 다른 소유권 차단 → 로그아웃/재로그인 → 삭제 후 연결 처리를 확인한다. 사주 입력이 인증 공급자로 전달되지 않는지도 확인한다.

결제: NICEPAY 테스트 상점의 실제 결제창 → 서명 반환 → 거래 소속/금액 조회 → 서버 승인 → 상태 조회 → 결과 권한 → 전액 취소를 확인한다. 승인 응답 유실·웹훅 중복·브라우저 종료·미확정 거래 대사도 검증한다. 승인 전 `ready` 조회 가능 여부는 현재 구현의 외부 확인 사항이다. 모의 결제 통과를 이 증거로 쓰지 않는다.

키는 지정된 비공개 환경 설정으로 관리하며 채팅·문서·Git에 넣지 않는다. 기존 전자책 서비스의 운영 키나 DB를 복사하지 않는다.

## 4. 모니터링과 장애 대응

`health`는 읽기 전용 집계다. `worker`·`maintenance`는 작업/대사를 실행하므로 PGlite 사용 시 웹 서버를 먼저 종료한다. 외부 PostgreSQL은 승인된 실행 role과 스케줄러를 별도로 구성한다.

| 상태/종료 코드 | 의미와 대응 |
|---|---|
| `0` | 현재 집계에 조치 필요 사유 없음. 출시 승인·큐 비움 보장은 아님 |
| `2 / DELAYED_QUEUE` | 비교 생성 후 300초 이상 지났고 아직 queued인 요청 존재. worker 중단·실행 주기를 확인하고 한 번 처리한 뒤 재점검 |
| `2 / EXPIRED_LEASES` | 작업 중단 또는 lease 누락. worker 재개, 소진 실패는 사용자 재시도 경로 확인 |
| `2 / FAILED_JOBS` | 실패 남음. 원인 수정 후 해당 결과만 재시도. 무료권 반환·유료 권한 보존 유지 |
| `2 / PENDING_PAYMENTS` | 기존 거래 조회·대사를 먼저 수행. 새 결제를 유도하지 않음 |
| `1 / OPERATION_FAILED` | DB/설정/명령 실패. 비밀값이 포함될 원문 오류를 공유 로그에 출력하지 않음 |

`oldestQueuedComparisonSeconds`는 **현재 대기 작업에 연결된 비교의 최초 생성 후 경과 시간**이다. 재시도 후에도 비교 생성 시각은 같으므로 순수 큐 체류 시간이 아니다. 300초는 로컬 점검용 시작값이며 운영 SLO가 아니다. 호스팅 알림은 개인정보 없는 상태·코드·집계만 전달하도록 연결한다. 이 작업에서 스케줄러나 외부 알림을 등록하지 않았다.

## 5. 운영 정책 초안의 확정 항목

아래는 구현에 맞춘 제품·운영 초안이며 게시 가능한 최종 약관·개인정보 처리방침·법률 검토 결과가 아니다.

| 항목 | 현재 동작/초안 | 운영 전에 정할 것 |
|---|---|---|
| 수집·목적 | 입력 중 별명·생일·시간·관계 자동 저장, 계산·결과 재열람 | 운영자, 문의 채널, 적법한 처리 근거·동의 시점/문구, 제3자 정보 입력 기준 |
| 무료 베타 | 실제 과금 없음, 가상 정보로 로컬 검토 | 외부 체험 대상·기간·동의와 중단/삭제 절차 |
| 유료 상품 | 첫 상대 무료·추가 2,900원 계획 유지 | 판매 범위·가치·가격·사업자 표시, 환불 조건·처리 기간·연락처 |
| 공개 공유 | 새 기호 풀이에서는 공개 별명과 대화 주제, 링크 30일·철회 | 링크 보유자 열람·실명 별명 노출 고지, 배포 접근 정책 |
| 삭제 | 생일·차트·결과·공유·초안·세션·복구 정보 제거 | 보존할 최소 거래/동의/무료 이력과 로그인 식별자의 근거·기간, 백업 삭제 처리 |
| 만료 | 비활성 미연결 무주문 게스트 조건 충족 시 30일 정리, 세션/공유 만료 정리 | 전체 보관 기간·운영 스케줄·정리 실패 감시 |
| 지원·사고 | 복구 코드·결제 미확정 대사·삭제 차단 경로 | 담당자·접수 창구·응답 목표·사고 처리 절차 |

자동 저장 안내를 앞에 보강한 것이 운영 동의·제3자 정보 처리 승인을 완료한 것은 아니다. 실제 정책 확정 시 저장 동작·기록 버전·동의 흐름이 일치하는지 재검증한다.

## 6. 백업·복원·배포 복귀

현재 `test:postgres`는 임시 로컬 클러스터에서 전체 테이블·스키마·권한·스냅샷·작업 재개를 검증한다. 운영 백업 검증은 호스팅 환경에서 별도로 진행한다.

운영 전 기록할 증거: 백업 보관/암호화·접근자·복구 지점/목표 시간 → 별도 격리 DB 복원 → 제한 runtime/anonymous role 확인 → 가상 소유권·결과·공유 철회·결제 권한·대기 작업 한 번 재개 → 운영 DB와 연결되지 않았는지 확인 → 복구 시간·누락 범위·증거 보관 및 임시 복원본 파기.

배포 전 이전 앱 커밋과 DB 변경 호환성을 확인한다. 장애 시 이전 앱으로 복귀하고 파괴적 DB 역마이그레이션은 자동 실행하지 않는다. 미확정 결제는 거래 조회로 대사하고, 저장 결과는 버전 변경만으로 재생성하지 않는다. 이번 보완은 스키마·계산 버전·풀이 버전을 바꾸지 않는다.

## 공개 전 최종 확인

[담당 역할별 목록](launch-preparation.json)의 실제 근거를 연결한다. 사용자 요청으로 건너뛴 이해도 관찰을 제외하고 계산/전문가 감수·접근 제한·외부 인증/결제·유료 범위·운영 정책/복구를 확인한 뒤 상품 책임자가 공개 출시를 결정한다. 설명형 무료 비공개 체험과 원래 유료 궁합 상품의 출시 조건을 섞지 않는다.
