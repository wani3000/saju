# 풀이 조건과 출시 자료 후속 점검

2026-10-22. 사용자가 인증을 뒤로 미루고 가능한 풀이 감수·출시 준비를 계속하도록 요청했다. OpenAI/Supabase/NICEPAY 재인증·외부 호출은 수행하지 않았다. 공개 풀이 v8과 기존 결과를 보존하고 연구 종합 v3 및 오프라인 출시 점검을 보완했다.

## 풀이 감수와 수정

### 합화 방해 조건의 적용 범위

보존된 三命通會 1926의 [PDF128쪽](../research/validation/fixtures/reading-sources/sanming-1926-page-128.png)과 [129쪽](../research/validation/fixtures/reading-sources/sanming-1926-page-129.png)을 다시 읽었다. 원문 이미지의 SHA256도 명세와 대조했다. 새로운 판본이나 독립 정답을 확보한 것은 아니다.

| 기존 조항 | 유지한 범위 | 합성 회귀 조합 |
| --- | --- | --- |
| 갑기 사이의 무, 을경 사이의 갑 | 해당 합 상대 사이의 자리만 검사. 기둥 어딘가에 있다는 이유로 전체 불성립 처리하지 않음 | 24 |
| 병신의 정, 정임의 병, 무계의 기 | 선택한 일간 합 문맥에서 드러난 천간의 존재 검사 | 36 |

[60조합 보고서](../research/validation/reports/condition-boundaries.json)의 기대값과 관찰값은 일치했다. 방해가 안 보이는 경우는 합화 성공으로 승격하지 않는다. 시주를 제거한 같은 조합에서도 조건 통과/최종 성립을 확정하지 않는다. 이는 기존의 보수적인 조항 정규화를 검증한 것이며 다른 판본보다 우선하는 최종 합화 규칙을 채택한 것이 아니다.

원전22명조(극단 강약20 + 중화/계절 반례2)에서는 정확한 네 기둥의 출처 연결을 유지했다. 각 명조의 한 기둥씩 바꾼88개 합성 변형과 시간을 지운22개 입력을 검사해 원래 판어를 전용하지 않는지 확인했다. 변형 입력은 실제 출생 명조나 새로운 원전 판정 사례로 세지 않는다. 일반 강약·중화의 수치 경계와 합화 충분조건은 여전히 미확정이다.

### 검토 필요 표시의 누락 수정

기존 분석기는 `clockReview`/`boundaryReview` 필드가 존재하면 검토 대상으로 표시한다. 그러나 새 종합 분석은 필드 값이 참인지만 보아 `false`/`null`인 입력에서 보류 사유가 빠질 수 있었다. 이미 검증된 coverage 표시를 공통 기준으로 사용하도록 고쳤다. 실제 날짜 어댑터의 일반 출력은 객체 표시를 사용하므로, 공개 앱에서 강약을 잘못 확정했다는 사례를 발견한 것은 아니다. 연구 결과는 이전에도 최종 판정을 null로 유지했다.

네 기둥만 받은 연구 분석에서는 사령을 계산할 생년월일이 없는데도 해당 보류 사유가 빠져 있었다. 이제 `birth-input-required`에는 사령 미확정을 명시하고, 생일 경로에서 `single-command`가 확인될 때 그 사유만 제거한다. 강약·합화의 다른 미확정 사유는 남긴다. 개인 성격 판단에도 시간 모름/경계/시계 등 입력 보류와 상위 구조 검토 필요를 전달한다.

연구 버전은 `whole-chart-evidence-synthesis-research-v3`, 조건 순서 모듈은 `source-boundary-priority-review-v2`다. [종합 보고서](../research/validation/reports/whole-chart-synthesis.md)를 재생성했다. 구현: [종합 분석](../research/validation/whole-chart-synthesis.mjs), [새 회귀 검사](../research/validation/condition-boundaries.test.mjs).

## 출시 준비

- 설정 사전 검사에서 `NEXT_PUBLIC_OPENAI_API_KEY`, AI Gateway 키, 접근/인증/OIDC 토큰 이름도 차단한다. 값을 출력하지 않는다. 모델 이름·Supabase publishable key·NICEPAY 공개 client key는 구별한다. 실제 비밀 노출을 발견한 것은 아니며 새 연동 준비에 맞춰 누락된 차단 범위를 보완한 것이다.
- [현재 소스 현황](current-release-source-inventory.json)을 추가했다. 실제 앱 풀이 v8, 계산 v5, 종합 연구 v3과 **예전 v2 대상 출시 감수 자료**를 따로 기록한다. 예전 감수 자료가 현재 v8의 전문가 승인으로 보이지 않도록 한다. 기존 원전 자료/빈 감수 양식은 덮어쓰지 않는다.
- 두 연구 보고서 및 현재 소스 현황을 CI에서 재현·대조한다. 소스만 바꾸고 보고서를 갱신하지 않은 경우 실패한다. 현황 검사 통과는 외부 연동이나 출시 승인이 아니다.
- 사용자 테스트 생략 지시는 그대로 유지한다. 관찰0명·미완료 사실은 유지하며 생략 항목을 다시 요구하거나 통과로 바꾸지 않는다. 기존의 나머지7개 출시 항목은 미완료로 보존한다.

```sh
node research/validation/audit-condition-boundaries.mjs --check
node research/validation/audit-whole-chart-synthesis.mjs --check
npm run release:inventory --prefix web -- --check
```

공개 앱 문구/화면/풀이 버전 변경이 없어 이번에 재배포하지 않는다. API 비교는 계속 미실행이다. 다음 실제 출시 단계에는 일반 판정/전문 감수, 외부 로그인·결제, 호스팅 운영·문의/보관 정책 등 기존 미완료 근거가 필요하다. 이 소프트웨어 검사를 명리 적중률이나 승인 증거로 바꾸지 않는다.
