# 김춘배 훈장 개인정보 처리방침 초안

상태: **게시 전 검토용·시행일/책임자/문의 주소 미정**. 현재 구현 사실과 제안 정책을 구분한다. 체크박스나 새 동의 절차를 이 문서만으로 자동 추가하지 않는다.

## 현재 처리하는 정보

| 구분 | 정보와 목적 | 현재 보관/처리 사실 |
|---|---|---|
| 로그인 | Supabase 사용자 식별자와 앱 계정 연결, 선택 닉네임·프로필 사진 URL | 로그인·프로필 표시·내역 소유권 확인. 회원 유지 동안 보관하는 정책 채택. 탈퇴·삭제의 잔존 항목은 아래 한계 참고 |
| 사주 입력 | 부를 이름, 생년월일, 양력/음력·윤달, 시간 인지 여부와 입력 시각, 두 사람의 관계 | 입력 중 초안 저장, 계산·결과 생성/재열람. 초안 내용은 마지막 수정30일, 저장 결과는 회원 유지/이용자 삭제까지라는 정책 채택 |
| 계산·결과 | 입력 스냅샷, 차트, 엔진/풀이 버전, 생성 상태 | 생성 당시 결과 보존. 사주 생일을 인증 공급자에 보내 계산시키지 않음 |
| 이용/결제 | 주문·거래 식별자, 금액·상태, 승인/취소 및 이용권 이력 | PG 대사·내역·중복 방지. 카드번호/카드 비밀번호를 앱 DB에 직접 보관하는 구조가 아님 |
| 공유 | 공개 별명·대화 카드, 링크 해시·만료·철회 상태 | 링크30일 만료, 철회 즉시 열람 차단. 만료/철회 행의 물리 정리는 retention/maintenance 실행 시 처리 |
| 인증/보안 | 세션 해시, 임시 OAuth/이관·결제 반환 상태, 제한/운영 이벤트 | 세션30일, OAuth/이관10분, 결제 시도20분의 유효기간. 만료 거절과 물리 삭제 주기는 서로 다름 |

로그인 전에도 방문 세션이 만들어질 수 있으나, 실제 생일 입력은 카카오 로그인 후로 제한한다. 제공하지 않은 프로필을 임의로 만들어 저장하지 않는다. 서비스는 현재 생성형 AI 설명 API를 활성화하지 않았으며 생일/풀이를 외부 LLM으로 보내는 운영 기능은 없다.

## 보유·파기와 삭제의 실제 범위

앱 삭제는 생일/차트/결과/초안/공유·세션·복구 정보와 표시 프로필을 지우거나 비운다. 그러나 주문·거래/기존 동의·무료 이용·작업/이용권·내용을 비운 비교 기록과 계정 연결 식별 표지는 남는다. 익명화나 잔존 정보 최소화가 완료됐다는 뜻은 아니다. 이 정보의 처리 근거·최소 항목·분리 보관·보유 종료/파기 작업은 출시 전에 확정해야 한다. Supabase 인증 기록이나 카카오 연결 해제는 별도 범위다.

계정 자체의 자동 정리는 주문/인증 연결/활성 세션/최근 초안이 없는30일 경과 게스트만 대상으로 한다. 회원 초안 내용의30일 정리는 계정 정리와 별개다. 회원 전체가30일 뒤 자동 삭제된다고 안내하지 않는다. 운영 이벤트는30일 경과분을 maintenance에서 정리한다. 원격 정기 실행은 아직 등록하지 않았다. 새 retention 명령은 결제 대사/결과 생성을 실행하지 않고 만료 정리만 수행한다.

법률 검토 시 목적 달성/기간 경과 정보의 파기와 법령상 보존 정보의 분리 보관을 확인한다([개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981), 시행2026-09-11). 거래기록의 법정 보존을 사주 원본 전체의 무기한 보관 근거로 사용하지 않는다. 백업 정책은 아래 채택값을 따르되 자동 보관/삭제와 복원 뒤 삭제·철회 재반영은 구축 전이다.

## 외부 처리와 공개 범위

카카오·Supabase 인증, Supabase PostgreSQL, Vercel 호스팅, NICEPAY 테스트 PG를 사용한다. 각각의 계약상 위탁/제공 관계, 실제 전송 항목, 처리 국가·접근/로그·재위탁 범위는 확정 목록에 남긴다. DB가 서울이라는 이유만으로 모든 처리/접근이 국내에만 있다고 표시하지 않는다. 국외 이전의 처리 근거·고지 항목은 [개인정보 보호법 제28조의8](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)을 대조한다.

현재 공개 공유는 링크 보유자 열람이다. 개인정보를 포함한 URL·코드·토큰·생일을 운영 알림에 넣지 않으며, 플랫폼 자체 로그/백업의 설정과 보관 기간은 별도 확인 대상이다.

## 정보주체 요청과 출시 전 결정

열람·정정·삭제·처리정지의 공식 접수 창구, 책임자, 확인 절차·회신 기준을 실제 운영자 정보로 채운다. 회원 탈퇴/외부 인증 연결 해제·아동 정보·상대방 정보 처리·각 처리의 근거와 동의 시점을 확정한다. 최종 개인정보 처리방침의 공개 및 법률 검토 완료를 이 초안 작성으로 대신하지 않는다.

## 채택한 보유·삭제 기본값 · 게시 전 적용 대조

사용자가2026-10-23 권장안 반영을 지시했다. 미완성 입력은 마지막 수정 후30일 경과 시 내용을 제거하고, 저장한 생일/사주 결과/관계 지도는 회원 유지 동안 보관하되 탈퇴 또는 이용자 삭제 시 종료한다. 장기 미접속만으로 유료 결과를 자동 삭제하지 않는다. 계정 전체 삭제 외에 개별 이야기 삭제 API와 프로필 확인 UI를 구현했다. Supabase 인증 삭제/연결 해제는 별도 대상이다.

만료 초안은 정리 전에도 서버 조회/계정 병합에서 개인내용을 사용하지 않는다. 정리 시 초안의 이름·생일 등 JSON을 비우고 계정ID·수정 번호·마지막 수정시각만 남긴다. 수정 번호를 재사용하지 않아 오래 열린 탭이 새 입력을 덮어쓰지 못하게 한다. 수정 번호 표지는 초안 내용과 구분하며 계정 삭제 때 함께 제거한다. 병합 시 초안의 기존 수정시각을 유지해 보관기간을 새로 늘리지 않는다.

삭제는 즉시 열람 차단·운영 DB 삭제 대상24시간 이내 처리를 목표로 한다. 미확정 결제/환불이 있으면 해결 후 진행하며 지연 사유를 안내한다. 거래/식별 잔존 기록과 외부 인증까지24시간 내 모두 제거된다는 보장은 아니다. 법정 거래기록은 계약/철회·결제/공급5년, 불만/분쟁3년, 표시/광고6개월을 기준으로 필요한 최소 정보만 분리 보관하는 설계를 확정한다([시행령 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1018638379)). 자동 분리/만료 파기는 아직 구현하지 않았다.

앱 운영 이벤트30일, 공유 링크30일 만료·즉시 철회, 일반 백업7일 순환 보관을 채택한다. 외부 플랫폼 로그·인증 자료는 별도 실제 설정과 계약을 확인한다. 백업 파일은 암호화하고 키와 분리 보관하며, 접근은 복구 담당자로 제한한다. 백업 자동 파기/외부 저장은 미구축이다. 삭제 정보는 복구 시 재반영하기 전 사용자에게 노출하지 않으며, 과거 사본의 잔존이 법적으로 허용되는 조건/파기 방식도 최종 검토한다. 백업7일은 모든 개인정보 삭제 의무에 일률적인7일 유예를 두는 뜻이 아니다.

운영 알림에는 고정 오류코드·집계·시각만 사용하며 생일/결과 원문·사용자/주문ID·세션·인증값을 싣지 않는다. 마케팅 알림은 기본 꺼짐을 채택하며 이번 작업에서 고객/운영자에게 외부 메시지를 발송하지 않는다.

## 개별 이야기 삭제의 범위

프로필의 ‘이 이야기 삭제’에서 확인 후 실행한다. 선택한 결과·공유 링크·비교의 입력/차트/입력 해시·해당 결제 반환 임시정보를 제거하고, 같은 두 사람ID의 임시 입력도 비운다. 다른 이야기와 로그인 세션은 유지한다. 동명이인이나 다른 상대의 초안을 일괄 삭제하지 않는다. 조회/관계 지도에서 빠지고 기존 링크는 열람할 수 없다. 이미 복사한 화면까지 제거하지는 못한다.

승인/취소 상태가 미확정이면 삭제를 거절하고 결제 내역 확인을 안내한다. 미결제 주문은 취소하고, 승인된 거래를 삭제 행위만으로 환불하지 않는다. 필요한 주문/거래와 무료 이용 이력·내용 없는 비교/이용권/작업 표지는 남는다. 이미 제공한 무료 이야기를 지워도 무료권은 새로 주지 않는다. 아직 제공하지 못한 무료 예약만1회 반환하고 오래 실행 중인 작업의 완료를 막는다.

새 SQL 스키마나 외부 관리자 자격 없이 구현했다. 늦은 결제 응답과 같은 요청 재전송은 삭제한 결과를 다시 생성하지 못한다. 백업 이전 삭제의 독립 원장/복원 재반영과 법정 기록 분리 파기는 여전히 미완료이며, 삭제 이후에 만든 합성 백업 복원 검사로 이를 대신하지 않는다.


## 최신 복원·운영 준비 후속

[전체 실행 후속](../remaining-launch-execution.md)의 격리 도구는 과거 사본에 그 이후 삭제/환불 상태를 재반영하고 세션/공유/작업을 닫는 훈련을 검증했다. 이는 독립 원장과 실제 운영 복구의 완성이 아니다. 관리 백업 순환과 읽기 전용 관측/검증된 사본 확인을 구현했으나 외부 저장/주기 실행·수신처는 미설정이다. 실제 고객 정보의 장기 보관/자동 파기를 켜거나 외부 인증 탈퇴·법정 기록 분리 처리가 끝났다는 고지는 게시하지 않았다.
