# 첫 베타 범위와 풀이 품질 기준

2026-10-19. 사용자가 출시 준비 1번(범위·정책 고정)과 2번(풀이 품질 보강)을 요청했다. 첫 검토 대상은 **점수 없는 사주 기호 설명판**으로 고정한다. 현재는 로컬 비공개 베타 후보이며, 외부 참가자에게 공개한 서비스가 아니다. 원래의 유료 궁합 상품 계획은 보류 상태로 유지한다.

## 고정한 범위

정책 원본은 [beta-scope.json](../research/validation/beta-scope.json), 문구 버전은 `source-observations-copy-v2`다. 검증기는 공개 승인·실결제·점수·시주 비교로 범위를 바꾸는 설정을 거절한다. 운영 차단은 기존 서버의 연구 모드 검사를 계속 사용한다. 이 정책 파일이 원격 접근 제어를 구현한 것은 아니다.

| 구분 | 이번 베타 기준 |
|---|---|
| 대상·접근 | 현재 로컬 검토. 초대받은 성인 대상 외부 체험은 접근 제어 검증 후 별도 시작 |
| 입력 | 한국 출생, 1908~2026 연구 범위. 운영 정확도 승인 전이며 역사 시각·절입 보호 유지 |
| 설명 | 태어난 날의 천간 오행, 연·월·일의 모든 후보에 공통인 합충 기호와 출처·확인 범위 |
| 후보 처리 | 후보 중 임의 선택·확률 부여 없음. 일부 후보의 합충은 확정 문장 제외. 시간 모름에 시주 보충 없음 |
| 관계별 문구 | 친구·가족·연인·동료의 대화 주제. 생일로 도출한 성격이나 관계 예측으로 표시하지 않음 |
| 저장·공유 | 생성 당시 결과와 규칙 버전 보존. 공개 카드에는 대화 주제만 전달 |
| 지도 | 저장 결과 모음. 궁합 점수·거리 순위 없음 |
| 비용 | 실제 과금 없는 베타. 기존 결제 화면은 모의·테스트 검증 경로 |
| 제외 | 성격·관계 결과 예측, 신강·신약·중화 및 합화 최종 판정, 궁합 수치, 실결제, 공개 출시 |

첫 상대 무료·추가 상대 2,900원이라는 기존 유료 계획은 취소하지 않았다. 위 범위의 채택은 그 가격에 대한 고객 검증이나 유료 풀이의 충분성을 입증하지 않는다. 유료 전환 시 제공 가치·상품 문구·산식 범위를 다시 확정한다.

## 문장 보강과 버전 보존

v2는 v1의 원전 기호 비교를 그대로 사용하고 설명 문구를 별도 버전으로 바꾼다. 제목은 “두 사람의 사주 기호”, 공개 제목은 “함께 이야기해 봐요”다. 일간을 처음 보는 사람도 이해할 수 있도록 태어난 날의 글자 한 개를 분류한 오행이라고 설명한다. 연주는 입춘, 월주는 절기 기준임을 명시한다.

한 사람의 기준 오행만 미확정인 경우 다른 사람의 확인된 오행은 유지한다. 천간 후보가 달라도 오행 배속이 모두 같으면 그 공통 오행은 표시한다. 합과 충이 동시에 있으면 둘 다 남기며 서로 상쇄하거나 가감점하지 않는다. 짝이 없다는 이유로 잘 맞거나 맞지 않는다는 결론을 쓰지 않는다. 시주를 알고 있어도 이번 두 사람 비교는 연·월·일만 사용한다.

기존 `source-observations-copy-v1`과 `example-copy-v1/v2`, 생성·공유된 스냅샷은 수정하지 않는다. 대기 작업은 요청 당시 버전으로 완성한다. 같은 입력의 기존 결과는 새 문구 때문에 재구매시키지 않는다. [이전 선정 근거](selected-reading-release.md)를 함께 보존한다.

## 원문 사례와 감수 범위

[검토 초안](../research/validation/reports/beta-quality-drafts.md)과 [구조화 보고서](../research/validation/reports/beta-quality-audit.json)는 문장·조건 17사례와 원문 명조 22개를 재현한다. 17사례에는 양·음력 같은 날짜, 시간 모름·시간 있음, 절입 경계, 1954년 시계 검토, 한쪽/양쪽 오행 미확정, 같은 오행의 복수 천간 후보, 짝 없음·합충 동시 존재, 관계 유형 4개가 들어 있다. 조건 분리를 위한 합성 기둥은 실제 출생일의 달력 기대값으로 사용하지 않는다.

원문 22개는 기존 오행별 과다·극성·부족·극약 20명조와 새 중화 예시 1개·득령만으로 최종 강약을 정할 수 없는 대조 1개다. 모두 원문 사례에 한정한 참조 자료다. 일반 명조의 신강·신약·중화 분류기로 확장하지 않았다.

추가 출처는 1947년 上海大東書局 『滴天髓闡微』의 PDF 190~191쪽(인쇄 48~49쪽)이다. [원본과 판본 정보](https://commons.wikimedia.org/wiki/File:SSID-11335994_滴天髓闡微.pdf), [쪽 이미지·체크섬 목록](../research/validation/fixtures/reading-sources/beta-quality-sources.json), [전사와 제한](../research/validation/fixtures/reading-sources/beta-moderation-cases.json)을 남겼다.

- **辛巳 甲午 癸卯 癸亥**: 원문 판어가 `中和純粹`이고 `巳亥逢沖`을 함께 설명한다. 충의 존재만으로 불균형·불량 관계라고 단정하는 가설에 대한 대조다. 이 충은 해당 개인 명조의 연·시지 관계이며, 베타의 두 사람 연·월·일 비교와 구분한다. 원문의 `無土`를 다른 판본의 지장간 목록에서 토가 전혀 없다는 뜻으로 전용하지 않는다.
- **己酉 丙子 癸未 戊午**: `癸日子月，似乎旺相，不知財殺太重`을 확인했다. 월령만으로 최종 신강이나 중화를 정하지 않는 대조다. 여기서 새 신약 문턱을 만들지 않았다. 뒤따르는 도덕·인격 비난과 길흉 서사는 서비스 문구에 넣지 않는다.

Codex가 수행한 것은 출처 정의·쪽 이미지 대조, 후보·예외 처리, 문장 명료성 및 기술 검증이다. **명리 전문가의 최종 감수와 실제 사용자 이해도 검토는 미완료이며, 관찰한 참가자는 0명**이다. 자동 테스트 통과로 이 승인 상태를 바꾸지 않는다.

## 다음 검토의 완료 조건

아래는 후속 검토를 실행할 때 사용할 기준이다. 승인자를 확보하거나 외부 사람에게 메시지를 보낸 것은 아니다.

| 전환 조건 | 담당·필요 근거 | 현재 상태 |
|---|---|---|
| 계산 정책 승인 | 계산 검토자: 역사 시각·절입 쟁점 및 지원 범위에 서명된 판정, 경계 회귀 검증 | 대기 |
| 설명의 명리 감수 | 명리 감수자: 22명조·17초안의 출처/용어/과잉 추론 여부 검토, 지적 사항 해결 기록 | 미완료 |
| 이해도 확인 | 실제 참가자: 아래 5문항 응답과 입력→결과→공유 관찰 기록. 오인 사례가 나오면 문구 수정 후 재확인 | 시작 전 |
| 외부 비공개 체험 | 개발·운영 담당: 접근 제한, 개인정보 동의·삭제, 제3자 결과 비노출을 별도 환경에서 검증 | 시작 전 |
| 유료 상품 전환 | 상품 책임자·감수자: 판매할 설명의 범위·가치·가격 확정. 수치 도입 시 별도 산식·근거·불변 스냅샷 승인 | 보류 |
| 공개 출시 | 운영 담당: 준비된 인증·NICEPAY 실제 테스트 왕복, 운영 정책·복구·배포 검증 | 보류 |

사용자 검토는 정답을 먼저 보여주지 않고 다음을 자신의 말로 설명하게 한다. 외운 답이나 단순 만족도만으로 이해를 인정하지 않는다.

1. 기준 오행은 사주 전체의 오행 비율인가? — 태어난 날의 천간 한 개의 분류임을 구분해야 한다.
2. 충이 있으면 관계가 나쁘거나, 짝이 없으면 잘 맞는가? — 둘 다 그런 결론을 내리지 않는다고 이해해야 한다.
3. 대화 제안은 생일로 판단한 성격인가? — 편집한 대화 주제임을 구분해야 한다.
4. 공유 링크에 생일·기호 근거가 공개되는가? — 공개 카드의 실제 내용과 비공개 결과를 구분해야 한다.
5. 규칙이 바뀌면 예전 결과와 비용도 바뀌는가? — 기존 스냅샷을 보존하며 자동 재구매하지 않음을 이해해야 한다.

## 재현 방법

```sh
node research/validation/audit-beta-quality.mjs --check
node research/validation/audit-beta-quality.mjs --release-check
pnpm --dir research/validation test
npm test --prefix web
npm run typecheck --prefix web
npm run build --prefix web
python3 tools/check_docs.py
```

`--check`는 자료 재현 여부를 검사한다. `--release-check`의 예상 종료 코드는 **2**다. 아직 없는 전문가·계산 승인과 사용자·외부 체험을 통과로 간주하지 않는다. 실제 실행 결과와 모바일 화면은 [QA 기록](../web/qa.md)에 남긴다.
