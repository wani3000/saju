# 월간·시간 천간 및 백업 복원 후속 감수

2026-10-20. 외부 인증·결제는 준비 후 진행한다. 이번 변경은 원문 대조·파생 계산 검사와 격리된 로컬 복구 검증이다. 엔진 `research-civil-midnight-v5`, 풀이 `source-observations-copy-v2`, 기존 구매·공유 결과를 유지한다.

## 원문에서 확인한 범위

1926년 『評註淵海子平』 권일의 **PDF 39쪽(인쇄 20쪽)·40쪽(인쇄 21쪽)**을 전체 페이지로 직접 확인했다. 원본 PDF SHA-256은 기존 [출처 기록](../research/validation/fixtures/reading-sources/source.json)의 `664bccd1ea4706c609df8ea6cd69a4565db97dc277e876fc22eb125ea41dcc9f`와 같다. 전체 페이지 이미지 2장과 해시·전사·시작값을 [별도 fixture](../research/validation/fixtures/reading-sources/month-hour-anchors.json)에 고정했다. 현대 번역을 복제하지 않았다.

| 기준 천간 | 寅월 시작 천간: 論年上起月例 | 子시 시작 천간: 論日上起時例 |
|---|---|---|
| 甲·己 | 丙 | 甲 |
| 乙·庚 | 戊 | 丙 |
| 丙·辛 | 庚 | 戊 |
| 丁·壬 | 壬 | 庚 |
| 戊·癸 | 甲 | 壬 |

월은 寅에서 한 자리씩 순행하며 시간 천간은 해당 일간의 子에서 순행한다는 구절을 확인했다. 이는 시작값 **10묶음**과 전개 규칙의 근거다. 120칸 전체가 별도 표로 수록돼 있다거나 14,400분의 독립 기록을 확보했다고 세지 않는다.

- 월주: 1984~1993의 10개 연간 × 寅~丑 12월 = **120조합**을 절입에서 떨어진 날짜에 대조했다. 월의 시작값과 순행을 확인하며 이 표로 천문 절입 순간을 검증하지 않는다.
- 시주: 기존 별도 수집 KASI 자료 중 **2026-02-10~19의 일진 10행**을 사용한다. 각 일간별 시작값에서 시주를 전개하고 매일 00:00~23:59 전체 **14,400분**의 일주·시주를 대조했다. 평상시의 고정 UTC+9를 사용하며 역사 시계의 추가 증거로 확대하지 않는다.
- 늦은 자시: 10일 × 23:00·23:59 = **20건**에서 자정·23시·분리 자시 정책의 차이를 검사했다. 현재 연구판의 자정 기준은 늦은 子에도 당일 일간을 쓰고, 나머지 두 구현은 시간 천간에 다음 날 일간을 쓴다.

전부 현재 계산과 일치했다. 계산식 수정이나 버전 변경은 하지 않았다. 자시의 현대 시각 범위·일주 교체 시점·서머타임·진태양시 여부를 이 구절이 확정한다고 해석하지 않는다. 원문의 천간 전개와 서비스의 시계 관습은 별개다. 시간 모름을 임의 시각으로 채우지 않는다.

이 구절은 강약·합화 충분조건이나 두 사람의 관계 효과·궁합 가중치를 제공하지 않는다. 기호 설명 v2에 성격·예측·점수를 추가하지 않았으며 기존 22명조·100개 풀이 조합의 범위도 유지한다. [구조화 보고서](../research/validation/reports/month-hour-audit.json)·[읽기용 보고서](../research/validation/reports/month-hour-audit.md)를 출시 종합 자료 재현에 연결했다.

## 별도 DB 복원 검증 보강

이전 검사는 백업 후 `results` 스냅샷만 비교했다. 이제 `test:postgres`가 직접 만든 임시 PostgreSQL 클러스터에서 다음을 확인한다.

1. 합성 계정·세션·복구 코드·초안, 무료/모의 유료 결과, 모의 환불 결과, 활성·철회·만료·환불된 공유, 대기 중 무료 작업을 만든다.
2. 공개 스키마 **21개 테이블의 전체 행·열**을 정렬 JSON의 SHA-256·행 수로 비교한다. 비어 있는 외부 인증 등의 테이블도 포함하지만 외부 왕복이 검증됐다는 의미는 아니다.
3. `pg_dump`/`pg_restore`로 별도 DB에 복원한다. 스키마 덤프를 비교해 제약·인덱스·ACL·RLS 정책이 같은지 확인한다. PostgreSQL의 무작위 `\restrict` 키만 비교에서 제외한다.
4. 관리자 대신 실행 role로 세션·초안·기존 결과·구매 이용권을 읽는다. 환불/다른 소유자의 결과, 철회/만료/환불 공유는 차단된다. 실행 role의 테이블 생성/삭제·마이그레이션 수정과 익명 role의 전체 테이블 읽기·계정 쓰기도 거절된다.
5. 복원된 대기 작업을 실행하고 다시 실행해 결과 1개와 무료권 세대가 유지되는지 확인한다. 기존 무료·구매 스냅샷도 동일하게 유지되며 복구 코드가 같은 계정으로 복귀하는지 검사한다.

테스트는 부모의 DB·인증·PG 설정과 `.env`를 상속하지 않는다. 연구 모드·모의 결제 및 `LC_ALL=C`를 명시한다. 환경 정리 후 macOS PostgreSQL이 로케일 미지정으로 시작하지 못하는 현상을 로그로 확인해 로케일을 고정했다. 결과·토큰은 출력하지 않고 복구 fixture를 임시 폴더의 권한 0600 파일에 보관한 뒤 클러스터·백업과 함께 지운다.

이는 로컬 기능·권한 복원 검사다. 운영 환경의 암호화·보관 주기·외부 권한·RPO/RTO·모니터링·실제 장애 대응 완료로 간주하지 않는다. 실제 운영 복원 리허설은 외부 준비 후 남아 있다.

## 재현과 남은 조건

저장소 루트에서:

```sh
node research/validation/audit-month-hour.mjs --check
pnpm --dir research/validation test
node research/validation/audit-release-readiness.mjs --check
npm run test:postgres --prefix web
python3 tools/check_docs.py
```

`audit-release-readiness.mjs --release-check`는 현재 **종료 코드 2**가 맞다. 계산 관습 운영 채택, 명리 전문가 감수, 실제 사용자 이해도 관찰, 외부 체험 접근 제어, 실제 인증·결제, 유료 상품 범위, 운영 리허설의 8조건은 계속 미완료다. 자동 테스트 성공이 이 조건을 승인하지 않는다.
