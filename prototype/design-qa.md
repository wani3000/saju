## Findings / 수정 이력

1. [P2, 해결] 초기 hero와 제목이 원본보다 작았다. hero 높이를 250→270px, 제목을 42→48px로 조정하고 간격을 재분배했다. [수정 전](qa/comparison-before.png)과 [수정 후](qa/comparison-after.png) 비교로 인물 중심 위계와 두 줄 제목을 확인했다.
2. [P2, 해결] 미리보기 안내가 홈 하단에서 잘렸다. 홈의 중복 안내를 제거하고, 입력 시작과 결과·공유 카드에는 예시임을 명시했다. 최종 홈의 가격과 주 행동이 보인다.
3. [P1, 해결] 긴 입력/결과 버튼에 초점이 가면 브라우저가 바깥 기기 프레임까지 스크롤해 상태 표시줄이 밀리고 닫힌 키보드가 나타났다. 앱의 초점 처리는 preventScroll을 사용하고 오류 위치는 내부 MobileScroll에서만 이동한다. 앱 통합부에서 프레임의 native scroll 원점을 유지한다. 보호된 런타임 파일은 수정하지 않았다. 주 흐름과 오류 재검증 후 기기 scrollTop=0, keyboard data-visible=false 확인. [최종 결과](qa/result.png), [날짜 오류](qa/date-error.png).
4. [P2, 해결] 키보드 ‘입력 완료’를 누르는 중 blur가 버튼을 ‘처음으로’로 바꾸는 문제가 있었다. 서로 다른 key와 포인터 초점 보존으로 해결. 입력 완료 → 오류 표시 및 수정 완료 → 확인 화면 복귀를 재검증했다.
5. [P2, 해결] 수정 화면을 다시 열 때 중복 input ID가 label을 이전 화면에 연결했다. useId로 화면별 식별자를 만들었다. 화면 재진입 후 ‘별명’ 접근성 이름으로 입력하고 수정 반영을 확인했다.

## 필수 비교 항목

- **폰트/타이포그래피:** Jua 제목과 Noto Sans KR 본문. 제목 48px/1.12, 일반 화면 제목 34px, 본문 18~20px. 두 줄 헤드라인·부제·3단계·가격의 줄바꿈을 확인했다. 원본의 더 두꺼운 둥근 획은 Jua와 완전히 같지 않은 P3 차이로 남긴다.
- **간격/레이아웃:** 중앙 wordmark, 오른쪽 지도, 큰 두 마리 hero, 제목→부제→단계→주 행동 순서를 유지했다. 상단 안전 영역은 기기 크롬 때문에 조정했다. iPhone/Pixel에서 주요 버튼이 잘리지 않으며 긴 내용은 내부 스크롤로 접근한다.
- **색/토큰:** 크림 #fffdf4, 갈색 #422719, 주황 #ff893c. 원본의 흰색 버튼 글자 대신 진한 갈색을 사용해 읽기 쉽게 조정했다. 버튼 형태와 색의 역할을 보존한 의도적 차이다.
- **이미지:** 선택한 자체 시안을 참고해 built-in image_gen으로 두 마리 hero와 주황·크림 아바타를 각각 제작했다. 투명 PNG이며 실루엣, 눈·볼·줄무늬·봉제 질감을 확인했다. 기기나 캐릭터를 CSS/SVG 그림으로 대체하지 않았다. Plant와 동작 아이콘은 Phosphor 라이브러리다.
- **카피/콘텐츠:** 홈의 제목·설명·첫 상대/추가 가격을 유지했다. 결과마다 예시를 표시하고 입력 생일에서 계산한 결과라는 주장을 하지 않는다. 음력/윤달은 입력 흐름만 제공한다는 한계도 화면에 표시한다.
